# Design — add-qr-codes

## Context

See `proposal.md` — Why. State: `LinkResource` (`src/Link/Api/`) is the API Platform resource of a link; its item operations use `LinkItemProvider` (404 for a non-UUID or unknown id before any authorization) and `security: is_granted("LINK_VIEW|EDIT|DELETE", object)` with `LinkVoter` voting on the DTO (owner or admin). `LinkResource::shortUrl` is `APP_PUBLIC_URL` + slug (`PublicUrl`). API Platform 4.3 is configured JSON-only (`formats: json`, `error_formats: jsonproblem`, `handle_symfony_errors: true`); an operation may override `outputFormats`, and content negotiation (`ContentNegotiationProvider` + `ContentNegotiationTrait::getRequestFormat`, `vendor/api-platform/state`, `vendor/api-platform/metadata/Util`) matches the `Accept` header against the operation's output formats — an absent or wildcard `Accept` takes the first declared format, an `Accept` admitting none throws `NotAcceptableHttpException` (406, rendered as problem details through the error formats). `use_symfony_listeners` is at its default `false` (`vendor/api-platform/symfony/Bundle/DependencyInjection/Configuration.php`; not set in `config/packages/api_platform.yaml`): every operation is served by `MainController`, which runs the provider chain (content negotiation → read through the operation's `provider` → declared-parameter validation → `AccessCheckerProvider` evaluating `security` with the provided object as `object`) and then the processor chain `write → serialize → respond` (`vendor/api-platform/symfony/Bundle/Resources/config/state/processor.php`). An operation with an explicit `controller` is routed to that controller directly and bypasses all of it — a custom controller therefore cannot rely on `provider`, `security` or `QueryParameter` (Gate 1 round 1, finding 1). `WriteProcessor` calls the operation's `processor` only when `canWrite()` is true, which `MainController` defaults to `!isMethodSafe()` — false for GET — so a GET operation must declare `write: true` for its `processor` to run; `SerializeProcessor` and `RespondProcessor` pass a `Response` through untouched (`$data instanceof Response`, `vendor/api-platform/state/Processor/`). Project processors are plain classes implementing `ProcessorInterface`, tagged by `autoconfigure` and referenced by class name in `processor:` (`UpdateLinkProcessor`). Declared `QueryParameter`s are validated by `ParameterValidatorProvider` into 422 problem details with `propertyPath` = the parameter name (established by the analytics reports). The PHP image ships `gd` (`.docker/php/Dockerfile`, `php -m`). `endroid/qr-code` 6.1.3 requires PHP ^8.4 and `bacon/bacon-qr-code` ^3 (`composer show -a`), PNG needs `ext-gd`. The brief's §7 exit criterion for this row: a snapshot test of the SVG and a voter test. High tier: Gate 1 on the artifacts, Gate 2 on the code.

## Goals / Non-Goals

**Goals:** one operation on the existing resource, reusing the existing 404-then-voter boundary unchanged; the image produced by one small renderer class behind the library; determinism asserted by a byte snapshot; the OpenAPI document truthful about the non-JSON response; errors in the API's one shape (problem details) for 401/403/404/406/422.
**Non-Goals:** see proposal. Design-level: no abstraction over "QR providers" (one library, one class); no image caching layer; no `_format` route suffix (`/qr.png`) — the brief's contract is `?format=png`.

## Decisions

1. **An API Platform operation served by `MainController`, rendering in a state processor — not a custom controller, not a plain route.** `LinkResource` gains `new Get(uriTemplate: '/links/{id}/qr', name: 'link_qr', provider: LinkItemProvider::class, security: 'is_granted("LINK_VIEW", object)', write: true, processor: LinkQrProcessor::class, outputFormats: ['svg' => ['image/svg+xml'], 'png' => ['image/png']], parameters: ['format' => new QueryParameter(constraints: [new Choice(['svg', 'png'])], description: …)], openapi: …)`. The pipeline is the framework's own: `LinkItemProvider` loads the `LinkResource` (404 first), the parameter validator renders a bad `format` as 422 on `format`, `AccessCheckerProvider` asks `LinkVoter::VIEW` on the provided resource exactly as `GET /links/{id}` does, content negotiation renders a JSON-only `Accept` as 406 — then `WriteProcessor` hands the resource to `LinkQrProcessor::process()`, which renders and returns a `Response`; `SerializeProcessor` and `RespondProcessor` pass it through. `write: true` is what makes the processor run on a GET (Context); it flags nothing else — there is no persistence and no `previous_data`. Alternatives rejected: a custom `controller:` — under the default `use_symfony_listeners: false` it is routed directly and none of `provider`/`security`/`QueryParameter` runs (finding 1), and the controller service would have to be public; `use_symfony_listeners: true` — a global switch that changes how every existing operation is served, for one image; a plain `#[Route]` controller (like `/health`) — outside the OpenAPI document (spec api-docs) and re-implementing the 404/voter sequence and the 422 shape by hand; an output DTO with an `image/*` encoder — encoders exist for structured data, an image is bytes.
2. **Format from the query parameter; `Accept` only gates.** `QrFormat` backed enum (`svg`, `png`) with `mimeType()`, `extension()` and a static `fromQuery(?string)` defaulting to `svg` (a backed enum's own `from()` is final and not nullable — finding 2); the processor reads `?format` (default `svg`) after the declared `Choice` constraint has already rejected anything else. `Accept` is matched against the operation's two image types by API Platform (absent/wildcard → served; only-JSON → 406) but does not select the format: `?format=png` with `Accept: image/svg+xml` still returns PNG — the contract is the parameter, the header is a gate. Documented in the operation description. Alternative — `Accept`-driven selection — rejected: browsers send `image/*,*/*`, which would make the default ambiguous, and the brief fixes `?format=png`.
3. **Renderer: `QrCodeRenderer::render(string $url, QrFormat $format): string` over `Endroid\QrCode\Builder\Builder`.** One builder call per request: `writer` `SvgWriter` or `PngWriter`, `data` = the short URL, `size` 512, `margin` 16, `errorCorrectionLevel` `Medium`, `roundBlockSizeMode` `Margin` (keeps the image exactly 512 px by absorbing the rounding into the margin — asserted by the PNG dimension test), UTF-8 encoding. The exact constructor signature and option names are verified against the installed `vendor/endroid/qr-code` at task 1.2, not assumed. Rendering is CPU-only, a few milliseconds, no I/O — nothing to cache (`Cache-Control: private, max-age=86400` lets the browser keep it a day, as the brief asks). Alternative — `bacon/bacon-qr-code` directly — rejected in the proposal.
4. **Response headers set by the processor.** `Content-Type` from the format; `Content-Disposition: inline; filename="<slug>.<ext>"` (the slug is `^[A-Za-z0-9_-]{3,32}$` — spec links "Slug rules" — so it is safe inside a quoted filename without escaping; asserted by a unit test on the header value for a slug with `-` and `_`); `Cache-Control: private, max-age=86400`; `Content-Length` by Symfony. The API firewall is stateless, so no cookie is ever set. API Platform's default `cache_headers.vary` is not applied to a pass-through `Response`; `Vary` is not needed because the format is chosen by the URL, not by `Accept`.
5. **Determinism and the snapshot.** SVG output of `SvgWriter` is a pure function of (data, options, library version). `tests/Fixture/qr/spring-sale.svg` is rendered once for `https://example.test/spring-sale` (the test base URL from `.env.test`'s `APP_PUBLIC_URL`, read from the container in the test so the fixture and the API agree) and compared byte for byte; a library upgrade that changes the markup fails the test on purpose — the fixture is regenerated and the diff reviewed. PNG bytes are not snapshotted (zlib output may differ across `gd` builds): the PNG test asserts the signature and `getimagesizefromstring` = 512 × 512 × `IMAGETYPE_PNG`. The spec's "deterministic image" scenario is asserted over HTTP for SVG (two identical bodies, a third link differs).
6. **OpenAPI.** The operation's `openapi: new OpenApiOperation(summary, description, responses: ['200' => new Response(description, content: new \ArrayObject(['image/svg+xml' => …, 'image/png' => …]))])` — API Platform derives the response content types from `outputFormats` itself; task 2.1 verifies with `GET /api/docs.json` whether the derived 200 already lists both types and adds the explicit `responses` only if it does not. The `format` parameter appears from the declared `QueryParameter` (schema enum `svg|png`). Alternative — leaving the QR operation out of the document — rejected: the brief's §4 table lists it among the API routes.
7. **Layout.** `src/Link/Qr/QrFormat.php`, `src/Link/Qr/QrCodeRenderer.php`, `src/Link/Qr/LinkQrProcessor.php` (`implements ProcessorInterface<LinkResource, Response>`, autoconfigured and referenced by class name like `UpdateLinkProcessor`). The QR belongs to the link bounded context (it renders the link's own URL), not to `Shared`. Tests: `tests/Unit/Link/Qr/QrCodeRendererTest.php` (snapshot, PNG size, both formats' mime and extension), `tests/Api/Link/LinkQrTest.php` (`LinkApiTestCase`: headers, PNG, 422/406, the authorization matrix, inactive/expired/deleted, OpenAPI).
8. **Dependency pinning and audit.** `make composer ARGS='require endroid/qr-code:^6.1'` — the lock pins 6.1.x; `make composer ARGS='audit'` must report no advisory for the three new packages; `composer.json` gets no `ext-gd` platform requirement beyond what the library itself declares as a suggestion, because the image already has it and CI runs `php -m`-equivalent by executing the PNG test.

## Applicability (high tier)

| Question | Applies? | Note |
|---|---|---|
| Crash before/after an external effect | n/a | a read-only GET: no write, no message, no cache store; a crash mid-render is a 500 problem details and nothing to undo |
| Concurrent writers | n/a | nothing is written; concurrent reads render independently |
| Money rounding | n/a | — |
| Empty/zero/null inputs | yes | `?format=` (empty) and unknown values → 422 on `format` (declared `Choice`); absent `format` → SVG; a malformed or unknown `id` → 404 before authorization; a link with an empty rules document or no clicks renders the same (only `shortUrl` matters). |
| Authorization boundary | yes | the same sequence as `GET /links/{id}`: the firewall first — `access_control ^/api/ ROLE_USER` answers 401 to every anonymous request, known or unknown id alike (finding 3) — then, for an authenticated caller, `LinkItemProvider` 404 before the voter, then `LinkVoter::VIEW` — owner and admin pass, stranger 403 problem details; asserted over HTTP for every case in `tests/Api/Link/LinkQrTest.php` including an anonymous request to an unknown id; failing inputs: removing `security` from the operation makes the stranger case answer 200; removing `write: true` leaves the processor unrun (the SVG header case fails). No new attribute, no new voter, no public route. |
| Deletion/expiry | yes | a deleted link → 404 (the provider finds nothing); inactive and expired links keep their code — the QR encodes a URL, the redirect enforces state at scan time (spec scenario). |
| Idempotency of retries | yes | GET without side effects; identical bytes for identical input (snapshot); `Cache-Control: private, max-age=86400` lets a client not retry at all. |

## Risks / Trade-offs

- [A library upgrade changes the SVG markup] → the snapshot test fails on purpose; regenerate the fixture, review the diff, commit both together.
- [`?format` and `Accept` could disagree (`?format=png` with `Accept: image/svg+xml`)] → the parameter wins and is documented as the contract; the header only gates JSON-only clients to 406. A client that cannot send `Accept: */*` sends `image/*`.
- [`Content-Disposition: inline` versus a download] → `inline` shows the image in a browser tab and still allows "save as"; the web UI change (row 11) may add `download` on its anchor; the filename is the slug, which the slug rules keep header-safe.
- [Rendering cost under abuse] → a few milliseconds per request, authenticated only; per-endpoint limits are row 10's business, and the private cache keeps browsers from re-requesting for a day.
- [`gd` missing in another deployment] → PNG requests fail with a 500 problem details naming no internals; the how-to states the requirement; SVG needs no extension.
- [`write: true` on a GET reads oddly] → it is the documented switch that lets a safe operation run its `processor` under `MainController` (Context); the processor performs no write, and the operation description says so. Re-check the flag's meaning on every API Platform minor upgrade (the test suite would notice: no `Content-Type: image/svg+xml`).
- [Three new packages in the supply chain] → pinned by the lock, `composer audit` in the task, no runtime I/O in any of them; flagged for review as a dependency change (AGENTS.md).

## Migration Plan

No schema change. Deploy: `composer install` brings the three packages; the operation appears in `/api/docs.json` on the next request. Rollback: remove the operation and the packages — no stored data depends on them.
