# Tasks — stretch-public-hosting

Tier `high`: every new or changed guard carries a demonstrated failing input — a
test that fails when the guard is removed — not only a test that passes.

Every command below is runnable as written from the repository root. Where a step
needs a public host name, it is marked as the user's manual step and produces no
checked task.

## 2. Start-time provisioning

- [x] 2.1 Write the **one-shot init service** that provisions (design decision 3, Gate 1 confirmation 1, finding 4): it compiles the asset map into the assets volume and runs `bin/console lexik:jwt:generate-keypair --skip-if-exists` into the keys volume, and it is the only writer of either. - [x] 2.2 **A partial pair is never served, and the next run repairs it** (Gate 1 confirmations 2 and 3, finding 4). Two file moves are two operations, so nothing here claims an atomic publication; the guarantee is the one the stack actually provides: provisioning generates into a temporary directory inside the same volume and moves both files into place, and **if it dies at any point the init service exits non-zero, so `service_completed_successfully` is false and no dependant starts**. Before deciding anything, the next run discards what it finds if the location holds one file alone, or a pair whose public key is not the one derived from its private key, and generates afresh. Implement that, and make the requirement's wording match it rather than promising atomicity. **Executed:** implemented in `.docker/php/provision.sh` — generation into a staging directory inside the keys volume inside the same volume, both files moved into place, and a repair pass that discards a lone file or a pair whose public key is not the one derived from its private key. The wording in the capability says what the stack really guarantees rather than promising atomicity.
- [x] 2.3 Verify the interruption the finding names, executed: interrupt provisioning **between the two final moves**, and record that (a) the init service exited non-zero, (b) the web, worker and scheduler services did not start, and (c) the next `up` removed the partial pair, generated a complete matching one, and only then let the dependants start — the four states recorded from `docker compose --env-file .env.local -f docker-compose.prod.yml ps` and the key diff. **Executed, all four states recorded.** With the interruption hook set: init exited **70**; `ps -a` showed `php created`, `worker created`, `scheduler created`, `caddy created` — none started — while only postgres and redis ran; the volume held `private.pem` alone. - [x] 2.6 Demonstrated failing input for the single writer: move provisioning back into the three services' own entrypoints, run 2.5's loop, and record the mismatched pair when it appears — then restore the init service. **Executed five times, and it did not reproduce — recorded as the negative result it is.** Provisioning was moved back into the three services' own entrypoints and the init dependency removed; on empty volumes all five runs still produced one matching pair. ## 13. Gate 2 round 1

- [x] 13.1 **Finding 1 — ownership that expires while the destructive work runs.** The Symfony lock took a fixed 3 600-second TTL that Symfony refreshes only on acquisition, and the shipped reload cadence is also 3 600 seconds, so a run that outlived its interval lost ownership mid-transaction. Replaced with a **transaction-scoped PostgreSQL advisory lock** — the idiom this repository already uses for click retention — taken as the first statement of the destructive transaction with `pg_try_advisory_xact_lock`. It has no TTL at all: ownership ends with the transaction and with nothing else, and a run that dies leaves nothing held.
- [x] 13.2 Verify, executed: `testASecondRunIsRefusedWhileAnotherHoldsTheLockHoweverLongItRuns` holds the lock on a second connection and asserts the command exits 1 saying a run is in progress and that no user row was written; `testTheLockIsReleasedWithTheTransactionSoTheNextRunProceeds` asserts the next run proceeds once that transaction ends. The first is the case no TTL-based lock can promise, because the holder has been holding for an unbounded time.
- [x] 13.3 The capability now requires ownership that does not expire on a clock, with scenarios for a slow run and for release, rather than "a lock for its whole run".
- [x] 13.4 **Finding 2 — no trusted country source in production.** The stack defaulted to the `header` resolver, which cannot work here: the application reads that header only for a request from a trusted proxy, and with a FastCGI upstream the address it sees is the visitor's. Every country rule would have fallen through as unknown while looking configured. The production default is now `geolite2`, which degrades honestly — a missing database logs a warning once per process and answers "unknown" — with a read-only mount for the database and `GEOIP_DATABASE_PATH` pointing at it.
- [x] 13.5 Verify, executed against the running stack: three redirects carrying `CF-IPCountry: DE` were recorded with `country = (null)` — Caddy strips whatever a client sends under that header, so it cannot be mistaken for an edge's answer even by a component that would otherwise believe it.
- [x] 13.6 **Not exercised, and said so:** a country rule *matching* through the real stack needs a provisioned GeoLite2 database, which needs a MaxMind licence — the operator's step, like the certificate. `docs/how-to/deploy.md` says how to provision it, what happens without it, and how the `header` resolver is configured behind an edge that does resolve the country.
