# Tasks — stretch-graphql

Tier `high`: a new dependency, a second entry point to the same authorization,
and a query language whose cost a caller chooses — the denial-of-service shape
the roadmap's `medium` does not cover. Gate 1 on the artifacts before any code,
Gate 2 on the diff, and a demonstrated failing input for every new guard.

No REST operation changes. `tests/Api` — the contract tests, the error
catalogue, the OpenAPI document tests — must pass untouched; if one of them
changes, the refactor of section 3 is wrong.

## 6. The cost model

- [x] 6.1 A GraphQL request consumes one token per **root selection** of the executed operation, refusing the whole request when the budget cannot cover it, before any field is resolved (design decision 3). Verify, measured against the running stack: one root selection leaves `X-RateLimit-Remaining: 599`, three aliases leave 596, introspection alone leaves 595 — one token — and a malformed body is 400. `tests/Unit/Auth/GraphQlCostTest.php` pins the algorithm with 28 cases. **The refusal half had no test** (Gate 2 round 1, finding 3); it now has two, and writing them found a real fail-open: `RateLimiterInterface::consume($tokens)` throws `InvalidArgumentException` when the request asks for more tokens than the limiter holds, and that exception was caught by the listener's fail-open branch, so a document larger than the whole budget was **answered** instead of refused. `ApiRateLimitListener` now catches it separately and answers 429. Verify, executed: `testADocumentOverTheBudgetIsRefusedWholeAndResolvesNothing()` asserts 429 with `application/problem+json`, a `Retry-After`, and — through `StatementRecorder` — that **no statement mentioning `links` ran at all**, which is what "before any field is resolved" means; `testADocumentWithinTheBudgetIsAnsweredWhereTheSameDocumentOverItIsNot()` runs the same three-selection document against a budget of three and gets 200, so the 429 above is the price and not the document. **That pair tested the wrong branch** (Gate 2 confirmation 1, finding 3): a three-token document against a two-token *window* exercises `consume()` refusing to reserve more than its own size, not the capability's case of a cost above what this caller has **left**. `testADocumentOverWhatIsLeftOfTheBudgetIsRefusedWithTheWholeContract()` is that case — five-token window, two spent, then a four-selection document — and asserts the whole contract: 429, `application/problem+json`, a `Retry-After`, `X-RateLimit-Limit: 5`, `X-RateLimit-Remaining: 3`, no statement touching `links`, and a three-selection document answered 200 straight afterwards, which proves the refused charge reserved nothing rather than merely claiming it in a header. Both 429s now carry the window: the over-capacity branch had no `RateLimit` to report, so it asks the limiter for the current state with `consume(0)`, which reserves nothing.
- [x] 6.2 The count is taken from the parsed document, by the algorithm decision 3 states. Verify, executed: cases for a named root fragment (2), an inline root fragment (2), two aliases of one field (2), the same field twice unaliased (2), `@skip(if: true)` still charged (2), introspection alone (1) and introspection beside a real field (2).
- [x] 6.2a Operation selection is tested in every shape it comes in. Verify, executed: a two-operation document with a valid `operationName` charges that operation (A→1, B→2, asserted separately); an `operationName` naming nothing is refused; a document with no operation and one with two operations and no name are both refused.
- [x] 6.3 A request that cannot be priced is refused without a token and without resolution. Verify, executed: thirteen cases — a body that is not a JSON object, a non-string `query`, non-object `variables`, `variables` as a JSON list of scalars, `variables` as a JSON list of objects, a non-string `operationName`, an unparseable document, no operation, two operations without a name, an `operationName` naming nothing, a **fragment cycle**, an undefined fragment, and an operation selecting nothing — each asserting the refusal names why and that the cost is 0. The `variables` check was **wrong when written** (Gate 2 round 1, finding 2): `json_decode(..., true)` maps both `{"n": 1}` and `[1]` to a PHP array, so a JSON list passed the object check. **The first fix was not enough either** (Gate 2 confirmation 1, finding 2): `array_is_list()` cannot tell `{}` from `[]` once both have become the same empty array, so an empty list was still accepted. The body is now decoded **as objects** (`json_decode($content, false, …)`) and `variables` must be a `\stdClass`, which keeps the distinction the wire format made: `{}` is priced, `[]` is refused like any other list. Verify, executed: three unit cases (`[1]`, `[{"n":1}]`, `[]`) refuse; `testAnEmptyVariableObjectIsAcceptedAndAnEmptyListIsNot()` asserts both halves in one place; `testVariablesMayBeAbsentOrNull()` pins that absent and `null` stay legal; and the API-level provider now sends a JSON list and an empty JSON list, each answered 400 problem details naming `"variables"`.
- [x] 6.4 REST is unaffected. Verify, executed: `tests/Api/Auth/ApiRateLimitTest.php` passes untouched — one token per REST request, as before, because `GraphQlCost::ofOneRequest()` is what a non-GraphQL path gets.
- [x] 6.5 The demonstrated failing inputs, executed and recorded: reducing operation selection to "the first operation" fails the named-operation cases; removing fragment expansion fails the fragment cases; and removing the cycle guard **exhausts 512 MB of memory** rather than failing an assertion — the denial of service written by the defence, exactly as the design predicted. That last mutation also uncovered a real latent fault of my own: `isAllIntrospection()` walked fragments with no cycle guard of its own and was protected only by `count()` running first and throwing. A defence that depends on the order two private methods are called in is a defence that breaks when somebody reorders them, so it now carries its own guard, and the mutation now fails an assertion instead of the process.
- [x] 6.6 The depth and complexity ceilings refuse what they are for, and their refusals are **GraphQL-shaped** unlike the ones above. Verify, executed: a 16-level document is refused with `Max query depth should be 10 but got 16.`, and 40 aliased collection selections with `Max query complexity should be 200 but got 360.` — while 20 of the same are answered, so the limit does the refusing rather than some other bound. Both are 200 with `errors`.
- [x] 6.7 Pricing a document is itself bounded (Gate 2 round 1, finding 1). The counter re-expanded every fragment occurrence, so a linear, acyclic document whose `F0` spreads `F1` twice, `F1` spreads `F2` twice and so on made the listener visit exponentially many selections — before API Platform's ceilings, which therefore could not protect the worker. Measured on the unfixed code: 22 fragments in 860 bytes priced at 2 097 152 tokens in **1.39 s**. `count()` now memoises each fragment's cost and saturates at `MAX_TOKENS + 1`, and a document over `MAX_TOKENS` (1000) is refused rather than priced. Verify, executed and measured after the fix: the same 22-fragment document (872 bytes) is refused in **0.0024 s**, the 40-fragment one the test sends (1 592 bytes) in **0.0009 s** and a 200-fragment one (8 292 bytes) in **0.0033 s**, each with `The document asks for more than 1000 reads.`; `testAFragmentTreeThatDoublesAtEveryLevelIsPricedPromptly()` asserts under 1.0 s and that the refusal names the ceiling, and `testACostAtTheCeilingIsStillPriced()` pins that a document of exactly 1000 root selections is priced at 1000 rather than refused, so the saturation is a ceiling and not an off-by-one.
- [x] 6.8 **The bound covers every walk, not only the counting one** (Gate 2 confirmation 1, finding 1). The memoised counter made the `me`-ending document prompt, but `isAllIntrospection()` runs after it with neither memo nor ceiling — and it only traverses the whole expansion when every leaf *is* introspection, so the identical hostile shape ending in `__typename` still cost 2^n. Two independent guards now: the ceiling is applied **before** that walk, and the walk memoises per fragment. Verify, executed as three mutations of the source: with **both** guards removed, `testAnIntrospectionOnlyFragmentTreeIsAlsoPricedPromptly()` did not finish in **300 s** and was killed; with only the memo removed it passes in 0.006 s; with only the ceiling moved back after the walk it passes in 0.006 s — so each guard alone is sufficient and neither alone was present before. `testAnIntrospectionOnlyDocumentUnderTheCeilingStillCostsOne()` pins that the guards did not turn introspection into a refusal: `{ ...a ...a }` over an introspection fragment is still one token.

## After every task above is complete — the gate, not a task

Gate 2 is requested once section 9 is done, and it is deliberately not a
checkbox: `scripts/gate-run.sh` runs `scripts/pregate-verify.sh` first, and that
floor rejects any unchecked task. The lifecycle steps are:

1. `scripts/gate-run.sh stretch-graphql 2 full`.
2. Fix every finding, update its Status in `review.md`, and re-review with
   `scripts/gate-run.sh stretch-graphql 2 confirm <round>`.
3. The gate has passed when the last Gate 2 record reads `approved` or
   `confirmed` with no finding row left `open`; `scripts/workflow-verify.sh
   merge stretch-graphql` is what checks that before the merge.
4. After the user merges: `scripts/workflow-verify.sh archive stretch-graphql`,
   then the archive commit on `main`, which syncs the two capability deltas and
   removes roadmap row 15.
