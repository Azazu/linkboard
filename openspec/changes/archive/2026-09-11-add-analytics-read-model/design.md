# Design — add-analytics-read-model

## Context

See `proposal.md` — Why. State: `clicks` (§3.4) is written only by `ClickRecordedHandler` through the DBAL — one row per redirect with `link_id`, `occurred_at` (timestamptz), `country`, `device_type`, `os`, `browser`, `is_bot`, `referer_host`, `visitor_hash`, `variant`, `resolved_by` — indexed by `idx_clicks_link_occurred (link_id, occurred_at)` and its partial twin `idx_clicks_link_occurred_human … WHERE NOT is_bot`; `links.click_count` is the eventually consistent denormalised count. `src/Analytics/` is empty. `LinkVoter` votes `LINK_VIEW|EDIT|DELETE` on the `LinkResource` DTO; `LinkItemProvider` answers 404 for unknown or malformed ids before authorization; `/api/v1/admin/` is `ROLE_ADMIN` by `access_control` and every admin resource repeats `security: is_granted("ROLE_ADMIN")`. API Platform 4.3 validates declared `QueryParameter`s through `ParameterValidatorProvider` and renders violations as 422 problem details whose `propertyPath` is the parameter key (`vendor/api-platform/symfony/Validator/State/ParameterValidatorProvider.php`); a `ValidationException` thrown by a provider renders the same way. Symfony Cache ships `cache.adapter.redis_tag_aware` (`RedisTagAwareAdapter`: requires the `noeviction` or a `volatile-*` policy and throws `LogicException` otherwise; the compose Redis sets no `maxmemory`, so it runs `noeviction`) and every adapter fails open — `getItem` catches and logs a fetch failure as a miss, `commit` logs a save failure, `invalidateTags` returns `false` (`vendor/symfony/cache/Traits/AbstractAdapterTrait.php`, `Adapter/AbstractTagAwareAdapter.php`). `REDIS_URL` already feeds the rate-limiter pool. The framework's `clock` service exists (`@clock`). Tests run inside per-test transactions (dama) against a real PostgreSQL 16 and share the dev Redis (keys prefixed per environment where the suite writes). PHPStan level 8; no new dependency; high tier (raised by the user at Gate 2 round 1) — Gate 1 on the artifacts and Gate 2 on the code.

## Goals / Non-Goals

**Goals:** every report number produced by one SQL statement over `clicks` (window functions where the brief names them) returned as an immutable DTO; a read model that references no entity and no ORM (asserted); declared, validated query parameters with a documented 422; the owner/admin boundary reused, not re-implemented; a tag-aware Redis cache with TTL 300 s that a cache outage cannot turn into a failed report or a failed link write; admin global statistics on the same code path; `EXPLAIN`-verified plans and an uncached p95 measured on one million clicks; a demo seed that produces the dataset in seconds with no credential in the repository.
**Non-Goals:** see proposal. Design-level: no HTTP cache headers on reports; no pagination of report items (bounded by `limit` ≤ 50 or by the vocabulary); no query-parameter filters beyond the five; no new index unless the measurement demands it (recorded in the appendix, decided then); no extraction of the period/bucket logic into a reusable "filter" — six explicit queries are the portfolio point.

## Decisions

1. **Layout — `src/Analytics/` as the read model, DBAL only.** `Report/Period` (readonly: `from`, `to` as UTC `\DateTimeImmutable`; `Period::defaults(ClockInterface)` = start of the next UTC day and 30 days before it; `Period::of(?string $from, ?string $to, ClockInterface)` parses RFC 3339, fills an omitted `to` with the default and an omitted `from` with 30 days before the *effective* `to` (so `to` alone still yields a 30-day window ending there), and applies the rules — order, ≤ 366 days — returning violations by parameter name; `previous()` = the same length ending at `from`), `Report/Granularity` (enum `hour|day`, `step()` interval literal, `maxDays()` 14 for `hour`), `Report/ReportRequest` (link id or null for global, period, granularity, limit, includeBots; `cacheKey(string $report)`), `Dto/*` (one readonly class per report, public typed properties, lists of readonly row objects — plain PHP so `serialize()` stores them in the cache and API Platform normalises them), `Query/LinkSummaryQuery`, `Query/TimeseriesQuery`, `Query/BreakdownQuery` (countries, devices, referrers, variants share the *count + share + rank* shape; four small methods over one private template), `Query/GlobalStatsQuery`, `Cache/ReportCache`, `Api/*` (resources and providers), all depending on `Doctrine\DBAL\Connection` only. The architecture test (`tests/Unit/Analytics/ArchitectureTest.php`) reads every file under `src/Analytics/` and fails on `App\Click\Entity`, `App\Link\Entity` or `Doctrine\ORM` — the cheapest enforcement of NFR-QA-2 and spec "Reports are computed by the database"; `deptrac` stays unadded per the process rule. Alternative — DQL over the `Click` entity — rejected: the brief forbids it (FR-ANL-1) and DQL has no `generate_series`, no `FILTER`, no window functions without extensions.
2. **SQL per report — one statement, bound parameters, a compile-time bot fragment.** Every query takes `:link_id` (uuid string), `:from`, `:to` (UTC timestamps, `Types::DATETIMETZ_IMMUTABLE`), and appends the constant fragment `AND NOT is_bot` when `includeBots` is false — a PHP-side branch between two literal strings, never a bound boolean `(:bots OR NOT is_bot)`: with a bound value the planner cannot prove the partial index `idx_clicks_link_occurred_human` applicable once it switches to a generic plan (pdo_pgsql prepares server-side), and the whole point of the partial index is the default report. No user input is ever concatenated; `granularity` and `limit` are bound (`date_trunc(:unit, …)` accepts a text parameter; the `generate_series` step is `(:step)::interval` from the enum's literal). Sketches (`c` = `clicks`):
   - *summary* — one statement with `FILTER` clauses: `count(*) FILTER (WHERE occurred_at >= :from AND occurred_at < :to) AS in_period`, `… FILTER (WHERE occurred_at >= :prev_from AND occurred_at < :from) AS in_previous`, `count(*) FILTER (WHERE occurred_at >= :today) AS today`, `count(*) AS total`, `count(DISTINCT visitor_hash) AS uniques`, `min(occurred_at)`, `max(occurred_at)` over `WHERE link_id = :link_id [AND NOT is_bot]`; `deltaPercent = round(100.0 * (in_period - in_previous) / in_previous, 1)` when `in_previous > 0`, else null — computed in SQL with `CASE`. The brief's `lag()` over two period buckets is equivalent; `FILTER` scans the link's rows once instead of bucketing them, and the running-total/rank/share windows appear in the other reports. `:today` and the default period come from the same `ClockInterface` reading, so "today" and the period cannot disagree (design decision 4).
   - *timeseries* — `WITH buckets AS (SELECT generate_series(date_trunc(:unit, :from), date_trunc(:unit, :to - interval '1 microsecond'), (:step)::interval) AS bucket), hits AS (SELECT date_trunc(:unit, occurred_at AT TIME ZONE 'UTC') AS bucket, count(*) AS clicks, count(DISTINCT visitor_hash) AS uniques FROM clicks WHERE link_id = :link_id AND occurred_at >= :from AND occurred_at < :to [AND NOT is_bot] GROUP BY 1) SELECT b.bucket, coalesce(h.clicks, 0) AS clicks, coalesce(h.uniques, 0) AS uniques, sum(coalesce(h.clicks, 0)) OVER (ORDER BY b.bucket) AS cumulative FROM buckets b LEFT JOIN hits h USING (bucket) ORDER BY b.bucket`. `:from`/`:to` are passed as UTC `timestamp` (without zone) so `generate_series` and `date_trunc(… AT TIME ZONE 'UTC')` compare like with like; the DST scenario of the spec is exactly what `AT TIME ZONE 'UTC'` guarantees regardless of the session `TimeZone`. Both series bounds are truncated to the bucket, so an unaligned `from`/`to` yields partial first/last buckets whose clicks are still filtered by the exact half-open bounds in `hits` (spec "Unaligned bounds give partial buckets"); a period shorter than a bucket yields the bucket it lies in (two when it straddles a boundary). `hour` over ≤ 14 days is ≤ 337 rows; `day` over ≤ 366 days is ≤ 367 rows.
   - *countries / referrers / devices / variants* — `SELECT key, count(*) AS clicks, round(100.0 * count(*) / sum(count(*)) OVER (), 1) AS share, rank() OVER (ORDER BY count(*) DESC) AS rank FROM clicks WHERE … GROUP BY key ORDER BY clicks DESC, key NULLS LAST LIMIT :limit`, `total = sum(count(*)) OVER ()` read from the first row (0 rows → total from a separate `count(*)`? no: when the grouped set is empty the total is 0 by definition). `key` is `country`, `coalesce(referer_host, 'direct')`, `device_type` / `os` (two statements), or `variant` with `AND resolved_by = 'variant'` for the variants report (whose rows add `count(DISTINCT visitor_hash)`). `rank()` (not `row_number()`) so equal counts share a rank, as the spec says. Devices and variants have no `limit` (vocabularies of ≤ 7 and ≤ 4 values).
   - *global* — `totalUsers`, `totalLinks`, `activeLinks` from `users`/`links` (`count(*)`, `count(*) FILTER (WHERE is_active)`), `totalClicks`/`clicksToday` from `clicks [WHERE NOT is_bot]`; *timeseries* is the link timeseries without the `link_id` predicate and without the `count(DISTINCT visitor_hash)` (same template, a `withUniques` switch — the distinct count over every link's rows was what missed NFR-PERF-2, Appendix); *top-links* is two levels — `pairs` = `(link_id, visitor_hash COLLATE "C" AS visitor, count(*) AS n)` over the range, `per_link` = `sum(n)`, `count(*)` per `link_id` — then the join to `links` for `slug` and `owner_id`, `rank()` and the total window. The count is exact: the whole hash is compared, under the `"C"` collation, i.e. byte equality — the same equality as the column's own (deterministic collation), minus the locale comparison that made `count(DISTINCT visitor_hash)` over every link's rows sort collated 64-character texts for 810 ms; the pairs sort in parallel workers instead, 239 ms p95 (Appendix; a 64-bit-prefix shortcut measured the same and was rejected at Gate 2 confirmation 2 as lossy — the same-prefix regression case `testTopLinksCountVisitorsByTheWholeHash` guards against it). Not applied to the per-link reports, which meet the target as they are.
   Alternative — a `click_daily` aggregate — rejected: stretch; the measurement (decision 9) decides whether it is ever needed.
3. **Parameters: declared `QueryParameter`s + cross-checks in the provider.** Each report operation declares its parameters with `constraints` so OpenAPI documents them and `ParameterValidatorProvider` renders violations as 422 with `propertyPath` = the parameter name: `from`/`to` — a strict RFC 3339 check (the exact constraint — `Constraints\DateTime` with `\DateTimeInterface::RFC3339` if it accepts the `Z` designator, else a `Regex` + parse callback — is verified in task 2.1 against the installed validator, both spellings `Z` and `+00:00` must pass); `granularity` — `Choice(['hour', 'day'])`; `limit` — `Regex('/^\d+$/')` + `Range(1, 50)`; `includeBots` — `Choice(['true', 'false', '1', '0'])`. Cross-parameter rules (`from < to`, span ≤ 366 days, `hour` ⇒ span ≤ 14 days) cannot be single-value constraints: the provider builds the `Period` and throws `ApiPlatform\Validator\Exception\ValidationException` with a `ConstraintViolation` whose property path is the parameter the spec names (`from` for order, `to` for length, `granularity` for the hourly limit) — the same renderer, the same shape (spec "Report parameters and period"). Effective values are read from `$context['request']->query` after validation (strings; `includeBots` parsed by the request object) and the defaults come from the clock. Alternative — `castToNativeType` — rejected: it needs a `castFn` per parameter and would still leave the cross-checks to the provider.
4. **Time comes from the clock service, once per request.** `Period::defaults()` and the summary's `:today` derive from one `ClockInterface::now()` converted to UTC; SQL never calls `now()`. Tests that assert numbers pass explicit periods; the default-period test asserts the day alignment relative to the clock. A `MockClock` is not installed into the container (the in-memory transport factory already holds the real clock at boot); determinism comes from explicit periods, alignment from arithmetic.
5. **Authorization: the provider asks the existing voter.** `LinkReportProvider` (one class, the report name in the operation's `extraProperties`) resolves the link as `LinkItemProvider` does — non-UUID or unknown → `NotFoundHttpException` first — builds the `LinkResource` through `PublicUrl` and calls `Security::isGranted(LinkVoter::VIEW, $resource)`; a refusal throws `Symfony\Component\Security\Core\Exception\AccessDeniedException`, which the API firewall and API Platform render exactly like an operation-level `security` refusal (403 problem details; asserted). The operations keep `security: 'is_granted("ROLE_USER")'` as the coarse net, the admin operations `is_granted("ROLE_ADMIN")` (plus `access_control` on the prefix). One voter, one subject type, one attribute — the permission matrix's "View a link's analytics: own / any" is `LINK_VIEW`. Alternative — teach `LinkVoter` to vote on report DTOs — rejected: a second subject type in the voter for the same rule, and every DTO would have to carry `ownerId` for the voter's sake. Alternative — `security: 'is_granted("LINK_VIEW", object.link)'` with a link inside each DTO — rejected: the link would serialise into every report or need per-DTO ignore attributes.
6. **API surface: one read-only resource class per report.** `Api/LinkSummaryReport`, `LinkTimeseriesReport`, `LinkCountriesReport`, `LinkDevicesReport`, `LinkReferrersReport`, `LinkVariantsReport` (the DTOs themselves carry `#[ApiResource]` with a single `Get` at `/links/{id}/stats/<report>`, `provider: LinkReportProvider`, `stateless`), and `AdminSummaryReport`, `AdminTimeseriesReport`, `AdminTopLinksReport` at `/admin/stats/<report>` with `AdminStatsProvider`. One class per report gives OpenAPI a named schema per response and keeps `description`s where the `polish-api-and-openapi` change will refine them; the DTO fields are camelCase and RFC 3339 timestamps per §4. Alternative — one `LinkReport` resource with six operations returning heterogeneous shapes — rejected: one schema for six shapes documents none of them.
7. **Cache: pool `cache.reports`, `ReportCache` as the single gate.** `config/packages/cache.yaml`: `framework.cache.prefix_seed: linkboard/%kernel.environment%` (test and dev share the Redis; their keys must not) and `pools.cache.reports: { adapter: cache.adapter.redis_tag_aware, provider: '%env(REDIS_URL)%', default_lifetime: 300 }`. `ReportCache::remember(string $key, list<string> $tags, callable $compute): object` = `$pool->get($key, fn (ItemInterface $item) => { $item->tag($tags); return $compute(); })` inside `try { … } catch (\Throwable $e) { warning('Report cache unavailable; report computed without it', ['exception' => $e::class]); return $compute(); }` — the adapter already degrades a fetch failure to a miss and logs a save failure, but the `LogicException` of a wrong eviction policy and a refused connection during `tag()`/commit are not all guaranteed to be swallowed by every path, so the gate makes the contract explicit (spec "Cache store unavailable"). Key = `<report>.<sha1 of linkId|from|to|granularity|limit|includeBots>` — the reserved characters of PSR-6 keys (`{}()/\@:`) never appear. Tags: `link-<uuid>` for link reports, `global` for admin reports. `forgetLink(Uuid)` = `invalidateTags(['link-<uuid>'])`, `forgetGlobal()` = `invalidateTags(['global'])`, both `try/catch (\Throwable)` → `warning('Report cache not invalidated', ['link_id', 'exception' => class])`. TTL 300 s is the brief's number; `generatedAt` is part of the cached DTO, so a hit returns the original computation time — the UI's "updated up to 5 minutes ago". Alternative — `TagAwareAdapter` over `cache.adapter.redis` — rejected: two round trips per read and a tag-version key per tag; `RedisTagAwareAdapter` is what the component recommends for Redis. Alternative — a hand-rolled key set in Redis — rejected: the component exists.
8. **Invalidation lives in the link processors, after the flush.** `UpdateLinkProcessor` calls `$reportCache->forgetLink($link->getId())` after `flush()` on every successful patch (a rejected patch never reaches it — spec scenario), `DeleteLinkProcessor` calls `forgetLink` and `forgetGlobal` after its flush, next to the counter's `forget`. A failure is logged at `warning` with the link id and the write stands (spec "Cache store down during a patch"). No Doctrine listener: the processors are the two places a link changes today, the web UI (row 11) will call the same services, and an entity listener would fire inside the flush where a cache failure could poison the transaction. Creation invalidates nothing (a new link has no cached reports; `global` totals accept 300 s of staleness). Alternative — invalidate `global` on every patch — rejected: the top-links report carries only immutable link facts (`slug`, `ownerId`) and counts that change with clicks, not with patches.
9. **`EXPLAIN` and the p95 on one million clicks (NFR-PERF-2).** `app:demo:seed --reset --clicks=1000000 --days=60` on the dev database, then each link report SQL (the exact statements of decision 2, default period, bots excluded and included) through `EXPLAIN (ANALYZE, BUFFERS)` via `make console ARGS='dbal:run-sql …'`, and a scratch PHP script (`docker compose exec -T php php <scratchpad>/bench.php`, not committed) running every statement 20 times through the DBAL to record the 95th percentile. Expected: the per-link plans use `idx_clicks_link_occurred_human` (default) or `idx_clicks_link_occurred` (`includeBots`) as an index or bitmap scan bounded by `(link_id, occurred_at)`; the summary's all-time aggregates scan the link's rows once by `link_id`; the admin timeseries has no `link_id` predicate and is expected to seq-scan the range — its time is recorded, and a `(occurred_at)` index is added in this change only if the admin report misses 300 ms *because of the scan* (the global reports are admin-only and cached; the write path pays for every extra index). Outcome in the Appendix: the admin reports first missed the target because of their distinct-visitor count, not the scan, so no index was added; after Gate 2 round 1 both global reports dropped the count (119 / 75 ms), and after Gate 2 confirmation 1 the user decided (proposal, User decisions): top-links gets its exact unique visitors back through the two-level statement of decision 2 (239 ms p95), the global timeseries stays without them (best measured formulation 356 ms). Plans and timings go into the Appendix of this file (task 5.1); the dev database is reseeded with the default 50 000 afterwards.
10. **`app:demo:seed` (`src/Shared/Demo/`): entities for users and links, one SQL statement per link for clicks, one transaction.** `DemoSeedCommand` (`#[AsCommand('app:demo:seed')]`, options `--clicks=50000`, `--days=60`, `--reset`) refuses when `kernel.environment` is `prod` (injected `#[Autowire('%kernel.environment%')]`, so the guard is a unit test) and when either demo e-mail (`demo@example.com`, `admin@example.com`) already exists unless `--reset`. Inside `Connection::transactional()`: (reset) load both users, collect their link ids, `remove()` them — `links` and `clicks` follow through the FK cascades — `flush()`; then two `User`s with `random_bytes(12)`-derived passwords (`bin2hex`, 24 characters) hashed by `UserPasswordHasherInterface`, the admin promoted; ten `Link`s from `DemoDataset` (constant slugs and targets; documents run through `RulesDocumentParser` so the canonical form is stored exactly as the API would — an invalid document is a bug caught by the seed's own test), some with `setClickLimit`, `setExpiry`, `replaceUtm`; `flush()`; then per link one `INSERT INTO clicks (…) SELECT gen_random_uuid(), :link_id, :from + random() * (:to - :from), <country CASE over random()>, <device/os/browser from one random draw so the triple is consistent>, random() < 0.05, <referer CASE with 40 % NULL>, encode(sha256(convert_to('demo-visitor-' || floor(random() * :pool)::text, 'UTF8')), 'hex'), <variant or NULL>, <resolved_by consistent with the document and the drawn device/country> FROM generate_series(1, :n)` with `:n` = the link's share of `--clicks` (fixed weights summing to 100 %, the remainder on the first link), `:pool` = `max(1, n / 4)` so visitors repeat; finally `UPDATE links SET click_count = (SELECT count(*) FROM clicks WHERE link_id = links.id) WHERE id IN (…)`. Any throwable inside rolls the whole transaction back — the former dataset stays, nothing new exists — and the command reports it and exits 1; only *after* the commit does it drop the former and new links' counters and cache tags (best effort, warnings), so a crash there leaves at most a stale counter key or a cache entry that expires (Applicability). A test-only DBAL middleware (`tests/Fixture/FailingStatement.php`) injects the failure on a chosen statement — the `click_count` update, after the former accounts were deleted and the replacement rows written — and the guarantee has its failing input: without the outer transaction the accounts and links written before the failure survive it (the fresh-seed case fails first, the reset case likewise). Output: a table with the two e-mails and their passwords, the link count and click count, `make worker` not needed (the seed writes the rows directly, like the handler would). Passwords are printed, never logged and never returned. `random()` in SQL, not PHP loops: 50 000 rows take well under a second; 1 000 000 a few seconds (decision 9). Alternative — Foundry factories with Faker in PHP — rejected: 50 000 entity inserts through the UnitOfWork are slow and the factories live under `tests/`. Alternative — fixed demo passwords — rejected by the security rules (no credential in the repository); the printed random password serves screenshots and reviewers equally.
11. **Tests.** *Unit*: `Period`/`Granularity` rules (defaults alignment with a fixed clock, order, 366 days, 14 days for `hour`, RFC 3339 parsing of `Z` and `+02:00`, previous period), `ReportRequest::cacheKey` determinism and distinctness, `ReportCache` degradation with a throwing pool stub (compute called, `warning` logged), the architecture scan, the seed's `prod` guard. *Integration* (`tests/Integration/Analytics/`, kernel + PostgreSQL): `tests/Fixture/ClickRows.php` inserts rows with explicit facts through the DBAL (the handler's column list); one test class per query asserting the spec's numbers — summary (period/previous/delta/today/all-time), timeseries (gap filling, partial first/last buckets of unaligned bounds and a sub-bucket period, the 337/367 maxima, DST/UTC, hourly, cumulative), breakdowns (share, rank ties, null groups, `direct`, variants' uniques and the `resolved_by` filter), bots toggle, global (totals, timeseries over links, top links with slug/owner/unique visitors — five clicks from one visitor count as one). *Api* (`tests/Api/Analytics/`, `WebTestCase` + JWT like `LinkApiTestCase`): the authorization matrix over the six reports (owner/admin/stranger/anonymous/unknown id/inactive link), the 422 matrix (malformed, out of range, inconsistent — one violation each, `propertyPath` as specified), defaults and echo, cache hit proven by `StatementRecorder` (no statement on `clicks` during the second request; identical `generatedAt`), different parameters → recomputed, invalidation on `PATCH` and on `DELETE` (then 404), `global` invalidated on delete (top-links no longer names the link), cache store unavailable (a `RedisTagAwareAdapter` on `redis://127.0.0.1:1` installed into `ReportCache` through the test container before the first request → 200 + `warning`), the admin matrix. `tearDown` clears the `cache.reports` pool (its namespace is `test`-seeded, so dev entries are untouched). *Seed* (`tests/Integration/Shared/DemoSeedCommandTest.php`, `CommandTester` on the kernel's application): `--clicks=500 --days=5` → two accounts (one admin), ten links with documents, 500 rows within 5 days, `click_count` equals rows, the invariants of spec "Small seed for tests", the printed password logs the demo user in through `/api/v1/auth/token`; second run → exit 1, unchanged; `--reset --clicks=300 --days=3` → new links, 300 rows, old links gone; failure injection through `FailingStatement` on the `click_count` update — a fresh seed leaves no account, link or row, a `--reset` leaves the former ids, password, links and rows intact. Every guard has its failing input in the commit body: removing `AND NOT is_bot` from the default fragment fails the bots toggle; dropping the left join fails gap filling; `row_number()` instead of `rank()` fails the tie case; dropping the provider's `isGranted` fails the stranger 403; removing `forgetLink` from the update processor fails the invalidation case; a bound `:bots` parameter instead of the fragment is checked by the `EXPLAIN` of decision 9 (plan shows the full index instead of the partial one).
12. **Logging and personal data.** New records: `warning` `{exception}` when the cache is bypassed, `warning` `{link_id, exception}` when an invalidation fails. Reports carry aggregates and hosts only — never a `visitor_hash` (it is counted, not listed). The seed prints credentials to the console and writes nothing about them to the log.

## Applicability (high tier)

| Question | Applies? | Note |
|---|---|---|
| Crash before/after an external effect | yes | Seed: users, links and click rows are written in one `Connection::transactional()` — a crash inside leaves nothing (spec "A failure during seeding SHALL leave no partial data"); the counter `forget()` and the cache invalidation run *after* the commit, so a crash between them leaves at most a stale counter key (harmless: the script lifts, never lowers — capability `redirect`) or a cache entry that expires within 300 s. Reports: the only side effect is the cache write, which the adapter and the `ReportCache` gate make fail-open (decision 7); a crash between compute and save costs one recomputation. Link processors: invalidation runs after the flush; a crash before it leaves a stale entry for ≤ 300 s, never a lost write. |
| Concurrent writers | yes | Two seeds at once: the unique index on `lower(email)` fails the second one inside its transaction — rolled back whole, the first dataset intact; the duplicate guard is a convenience, the index is the authority. Two identical report requests at once: both compute (no lock, no stampede protection) and the last save wins with identical content — accepted, the reads are idempotent. Reports never write `clicks` or `links`; the worker writes them concurrently and a report simply sees the rows committed at its snapshot (the spec's bounded staleness covers the cache, PostgreSQL's snapshot the query). |
| Money rounding | n/a | shares and `deltaPercent` are `round(…, 1)` percentages in SQL, not money |
| Empty/zero/null inputs | yes | A link without clicks → every count 0, `firstClickAt`/`lastClickAt`/`deltaPercent` null (spec scenario); an empty previous period → `deltaPercent` null; null `country`/`device_type`/`os` and null `referer_host` are groups of their own (`null` / `direct`); `variants` of a link without variant-resolved clicks → `total` 0, `items` empty; `from` = `to` → 422 on `from`; `limit` 0 / 51 → 422 on `limit`; an absent parameter keeps its default (`to` alone → the 30 days before it); `--clicks=0` seeds accounts and links with no rows and `click_count` 0; `--days=0` → refused. |
| Authorization boundary | yes | Per-link reports: the provider answers 404 for a malformed or unknown id *before* any authorization check, then asks the existing `LinkVoter` for `LINK_VIEW` on the `LinkResource` — owner and admin pass, a stranger gets 403 problem details, anonymous 401; asserted over HTTP for each of the six reports (`tests/Api/Analytics/LinkReportsTest.php`), and dropping the `isGranted` call fails the stranger case. Global reports: `security: is_granted("ROLE_ADMIN")` on every operation plus `access_control` on `/api/v1/admin/` — user 403 and anonymous 401 asserted for each of the three. The seed promotes the demo admin with the entity method `app:user:promote` uses; the generated passwords are hashed by the configured hasher and printed once; the command never runs in `prod` (unit-tested guard) and is not reachable over HTTP. |
| Deletion/expiry | yes | `--reset` deletes exactly the two demo accounts by their fixed e-mails; links and click rows follow through the existing `ON DELETE CASCADE` FKs (no hand-written deletes), counters and cache tags of the former links are dropped after the commit, refused without the flag, refused in `prod` (spec "Guards and re-runs", both guards with failing inputs). A link's `DELETE` drops its cache tag and `global`, and its reports answer 404 afterwards (spec links "Reports gone with the link"). Cache entries expire after 300 s by TTL; tags carry no TTL of their own and only ever grow by invalidation. |
| Idempotency of retries | yes | A repeated seed is refused (the dataset unchanged) instead of doubled — the safe direction; `--reset` is the explicit way to redo it. Report requests are idempotent reads; `forgetLink`/`forgetGlobal` are idempotent invalidations (a second call finds nothing to delete). No message, no queue in this change. |

## Risks / Trade-offs

- [Default period is day-aligned, not "the last 30 × 24 hours"] → chosen so identical default requests share one cache entry for a whole day (a moving `to = now` would make every request a miss); stated in the spec and the how-to; a client wanting a sliding window passes `from`/`to`.
- [Clients that pass `to = now` to the second defeat the cache] → their own choice; the web UI (row 11) uses the defaults or day-aligned pickers; documented.
- [Bounded staleness of 300 s, including after new clicks] → the brief's accepted trade-off; `generatedAt` in every report; invalidation on link changes only.
- [`count(DISTINCT visitor_hash)` over a busy link's 30 days] → an index-bounded scan plus a hash aggregate; measured on one million rows (decision 9); a `click_daily` aggregate is the stretch answer if it ever misses the target.
- [The admin timeseries and top-links scan the whole period without a `link_id` bound] → measured on one million clicks (Appendix): with `count(DISTINCT visitor_hash)` they took 534 / 810 ms p95 and an `(occurred_at)` index was measured as pointless (the scan is ≈100 ms of it). Top-links keeps its exact unique visitors through the two-level (link, whole hash under `COLLATE "C"`) statement — 239 ms p95, a thin margin on the 300 ms target that the cache (TTL 300 s) covers in practice; the global timeseries carries none (every formulation measured 356–575 ms) — accepted by the user (proposal, User decisions); the stretch `click_daily` aggregate is the way if per-bucket global visitors are ever wanted.
- [`RedisTagAwareAdapter` refuses an eviction policy other than `noeviction`/`volatile-*`] → the compose Redis has no `maxmemory` (so `noeviction`); the how-to states the requirement for other deployments; the `ReportCache` gate turns the `LogicException` into a computed report plus a `warning`, never a 500.
- [Tag invalidation on a shared Redis] → keys are namespaced by `prefix_seed` per environment, so the test suite's `clear()` and the dev stack never touch each other's entries.
- [Equal counts share a rank, so `items` can hold more than `limit` distinct ranks' worth of ties truncated arbitrarily] → `ORDER BY clicks DESC, key` makes the truncation deterministic; ranks are informative, not positional.
- [`deltaPercent` is null when the previous period is empty] → stated; an infinite growth is not a number.
- [Variants report ignores clicks not resolved by a variant] → stated in the spec; a variant's share is meaningful only among variant-resolved clicks.
- [The seed's generated passwords are lost when the console output is gone] → `--reset` regenerates everything in a second; there is no recovery path by design (no credential is stored in clear anywhere).
- [The seed's SQL distributions are hard-coded] → they are demo data; the shapes (nulls, bots, variants, repeats) are asserted, the proportions are not.
- [1 000 000 seeded clicks in the dev database during the measurement] → reseeded to 50 000 afterwards (task 5.1); the test database is untouched.

## Migration Plan

No schema change. Deploy: code + `config/packages/cache.yaml`; the pool creates its keys on first use; Redis must run `noeviction` or a `volatile-*` policy (compose: default). Rollback: remove the code; the pool's keys expire within 300 s (tags live until their entries expire — harmless). `app:demo:seed` is opt-in and refuses `prod`.

**Every report meets the target** — per-link (worst: devices, 230 ms for two statements) and global (timeseries 119 ms; top-links 239 ms with its exact unique visitors, the thinnest margin). Two findings worth recording:

1. **The planner takes the FK index `idx_20da1901ada40271 (link_id)`, not the composite `idx_clicks_link_occurred` nor the partial `_human` one.** Both composite indexes are applicable (the bot fragment keeps `NOT is_bot` visible), but a 30-of-60-day window keeps half of the link's rows, so bounding the range in the index buys little and the smaller single-column index wins; on the seeded data `occurred_at` is in random heap order, which also makes a range scan of the composite index unattractive. Hiding the FK index (`DROP INDEX` inside a rolled-back transaction) forces the composite index and changes nothing: summary 186 ms, timeseries 91 ms, countries 106 ms. Production rows arrive in time order, so the composite index gains heap correlation there — worth re-checking once real data exists, no action now.
2. **The cost is the aggregation, not the scan.** Every statement spends most of its time sorting the link's rows for `count(DISTINCT visitor_hash)` (external merge at the default 4 MB `work_mem`); `SET work_mem = '64MB'` turns the sorts in-memory and is *not* faster (summary 202 ms, admin timeseries 652 ms) — the sort is CPU-bound. The index scans themselves take 15–30 ms.

**The global reports first missed the target because of the distinct-visitor count, not the scan** (Gate 2 round 1, finding 4): the Seq Scan of the 466 k rows in range is ≈100 ms of the 534 ms; the rest was the sort for `count(DISTINCT visitor_hash)` over all of them — a sort of collated 64-character texts — which no index on `clicks` removes, so the `(occurred_at)` index of decision 9 was measured as pointless and **not added**. The original brief on `main` named no unique visitors for the global reports (FR-ANL-4: clicks per day, top links by clicks); this change's own refinement had added them to top-links and given the global timeseries the per-link shape, and Gate 2 round 1 dropped both (119 / 75 ms). Gate 2 confirmation 1 asked for the user's explicit decision on that revision (proposal, User decisions): **top-links keeps its exact unique visitors** — the two-level statement of decision 2 sorts `(link_id, visitor_hash COLLATE "C")` pairs in parallel workers, 239 ms p95 on a fresh one-million seed; failing inputs: `sum(n)` in place of `count(*)` at the second level (visitors equal clicks, both top-links tests fail) and a 64-bit prefix of the hash in place of the whole hash (the same-prefix regression case counts 1 instead of 2 — the shortcut Gate 2 confirmation 2 rejected); **the global timeseries stays without them** — every formulation measured (`COLLATE "C"`, 64-bit prefix, pairs, `work_mem` 4/16/64 MB) lands between 356 and 575 ms. The per-link reports keep their unique visitors (bounded by one link, within the target). If the per-bucket distinct count over every link is ever wanted, the stretch `click_daily` aggregate (pre-aggregated visitors per day and link) is the way. Recorded in Risks / Trade-offs.

Reseeded afterwards with `app:demo:seed --reset` (50 000 clicks); the shipped global statements were re-measured on a fresh one-million seed the same way.
