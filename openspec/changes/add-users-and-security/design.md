# Design — add-users-and-security

## Context

See `proposal.md` — Why. State after `scaffold-symfony-app`: Symfony 8.1, API Platform 4.3 under `/api/v1` (JSON only, problem details), Doctrine ORM 3 with attribute mapping over `src/`, Twig installed for Swagger UI, Redis available, no security bundle, no entity, no migration. Constraints: DataMapper (entity without framework base class, repository interface + Doctrine implementation), `final` by default, UUID v7 ids, every guard with a failing-input test, `high` tier.

## Goals / Non-Goals

**Goals:** the account model and both authentication paths exactly as specified, the first authorization boundary (admin), the first validated input (422 shape), a rate limit that is real (Redis-backed) and tested.
**Non-Goals:** see proposal; also no user profile editing, no email change, no password change (not in the specification).

## Decisions

1. **`User` is a plain final entity in `src/Auth/Entity/User.php`** implementing `UserInterface` and `PasswordAuthenticatedUserInterface` (those are interfaces, not base classes — DataMapper stays intact). Fields per §3.1; `roles` stored as JSON, `getRoles()` always adds `ROLE_USER`. Identifier `Uuid` v7 generated in the constructor (`Uuid::v7()`), not by Doctrine. Repository: `UserRepositoryInterface` (`findByEmail`, `add`, `findById`) in `src/Auth/`, `DoctrineUserRepository` beside it; the security user provider is a small `EntityUserProvider`-free class calling the repository (`UserProviderInterface`), so the provider honors the case-insensitive lookup (`lower(email)`).
2. **Case-insensitive uniqueness by a functional index**, not by lowercasing on write: migration adds `CREATE UNIQUE INDEX uniq_users_email_lower ON users (lower(email))`; the repository queries `LOWER(u.email) = LOWER(:email)`; the validator uses a custom `UniqueEmail` constraint backed by the repository (no `UniqueEntity`, which would compare case-sensitively). Failing input: `Ann@Example.com` after `ann@example.com`.
3. **Registration as an API Platform resource with a DTO**: `src/Auth/Api/RegistrationInput` (email, password with `#[Assert\Email]`, `#[Assert\Length(min: 12)]`, `UniqueEmail`) exposed via `#[ApiResource]` on a `UserOutput`/`Registration` resource with a single `Post` operation `uriTemplate: '/auth/register'`, `input: RegistrationInput`, `processor: RegisterUserProcessor`, `security: 'is_granted("PUBLIC_ACCESS")'`, output `UserOutput` (id, email, roles, createdAt). The processor hashes with `UserPasswordHasherInterface` and calls the repository. Validation errors come out as 422 problem details with `violations` through API Platform's validator integration — this is where spec `api-error-format` gets its deferred requirement. Alternative rejected: a plain controller (would bypass the OpenAPI document and the uniform error path).
4. **Two firewalls in `security.yaml`**: `api` (`pattern: ^/api`, `stateless: true`, `provider: app_users`, `json_login` on `/api/v1/auth/token` with Lexik's success/failure handlers, `jwt: ~` authenticator, `entry_point: jwt`) and `main` (`form_login` `/login` with `enable_csrf: true`, `logout` `/logout`, `login_throttling` off — our own limiter covers it uniformly). `access_control`: `^/api/v1/auth/` PUBLIC_ACCESS, `^/api/docs` PUBLIC_ACCESS, `^/api/v1$` PUBLIC_ACCESS (documentation), `^/api/v1/admin/` ROLE_ADMIN, `^/api/` ROLE_USER, `^/(login|register)$` PUBLIC_ACCESS, `^/health` PUBLIC_ACCESS. Password hasher `auto`. `role_hierarchy: ROLE_ADMIN: ROLE_USER`.
5. **JWT via `lexik/jwt-authentication-bundle` 3.2**: RS256 keypair under `config/jwt/` (gitignored), `JWT_PASSPHRASE` from `.env.dev` / `.env.test` (dev/test-only values, committed the way Symfony commits `APP_SECRET` in `.env.dev`) and from the real environment in prod; `token_ttl: 3600`; the success response is customized (event `lexik_jwt_authentication.on_authentication_success`) to add `expiresAt` (RFC 3339 UTC) next to `token`. Failure/invalid/expired/not-found events answer `application/problem+json` 401 through one subscriber (`JwtProblemDetailsSubscriber`) so the API never emits Lexik's default `{"code":401,"message":...}` shape. `make jwt-keys` (`lexik:jwt:generate-keypair --skip-if-exists`) is part of `make init` and of the CI step before `make check`.
6. **Blocked users**: `src/Auth/Security/BlockedUserChecker` (`UserCheckerInterface`) throws `CustomUserMessageAccountStatusException('blocked')` in `checkPreAuth`, which fires on every stateless JWT authentication and on every session request (the firewall re-checks the user through the provider's `refreshUser` → checker). API: the authentication failure is turned into 403 problem details `detail: blocked` by the same subscriber as decision 5 (Symfony's `AccountStatusException` is distinguishable from bad credentials); web: form login failure message. Failing input: block a user holding a valid JWT and replay the token → 403.
7. **Admin operations as API Platform operations on a `UserAdmin` resource** (`GET /admin/users` collection with pagination via a state provider over the repository; `POST /admin/users/{id}/block` and `/unblock` with processors), `security: 'is_granted("ROLE_ADMIN")'` at operation level. Self-block returns 422 via a validation on the processor input (`ValidationException` with a violation on `id`). Audit: the processors log `info` with `action`, `actor_id`, `target_id` through the `audit` Monolog channel (JSON in prod as everything else).
8. **Rate limiter**: `framework.rate_limiter.auth_ip` `policy: sliding_window, limit: '%env(int:RATE_LIMIT_AUTH_PER_IP)%', interval: '1 minute'`, storage the Redis-backed `cache.rate_limiter` pool (`framework.cache.pools`), lock factory on Redis too. A `kernel.request` subscriber (`AuthRateLimitSubscriber`, priority above the firewall) applies it to `/login`, `/register` (POST only) and `^/api/v1/auth/` (POST); on rejection it returns 429 with `Retry-After`, problem details under `/api`, a small Twig page otherwise. Client IP from `Request::getClientIp()` with `framework.trusted_proxies: '%env(TRUSTED_PROXIES)%'` and `trusted_headers: ['x-forwarded-for','x-forwarded-proto']`. Tests use a dedicated limiter storage (in-memory `cache.adapter.array`) so the counter starts empty per test process; the Redis path is verified once by an integration test hitting the real pool. Failing inputs: the 11th request → 429; an untrusted peer's `X-Forwarded-For` is ignored (counted against the real peer).
9. **Console commands** `app:user:promote`/`app:user:demote` in `src/Auth/Command/`, using the repository; exit code 1 for unknown email.
10. **Web pages**: `templates/security/login.html.twig`, `templates/security/register.html.twig` extending `base.html.twig`, Symfony Form `RegistrationFormType`, controller `src/Web/Security/*`. Intentionally bare; `add-web-ui` restyles them. Post-login target: `/` for now (a placeholder page listing "dashboard arrives with add-web-ui"), documented as temporary.
11. **Tests**: Unit — `User` roles normalization, `BlockedUserChecker`, DTO constraints; Integration — repository case-insensitive lookup against PostgreSQL, unique index (failing input: duplicate differing by case raises), promote/demote commands via `CommandTester`, Redis-backed limiter increments; Api — registration (201, 422 shapes, duplicate), token issue/use/expired/missing/wrong password, `/me`, admin list/block/unblock matrix (admin / user / anonymous / self / unknown id / idempotent), blocked-with-valid-JWT → 403, rate limit 11th → 429, spoofed `X-Forwarded-For`; Web — register → redirect to login, login OK, wrong password, missing CSRF, blocked user message. Foundry factory `UserFactory` in `tests/Factory/`.

## Applicability (high tier)

| Question | Applies? | Note |
|---|---|---|
| Crash before/after an external effect | yes | registration and block/unblock are single-transaction writes; the audit log line is written after the flush succeeds, so a failed flush leaves no log line and no row |
| Concurrent writers | yes | two simultaneous registrations of the same email: the unique index (functional, on `lower(email)`) is the authority; the second insert fails and is mapped to 422 by the processor (the validator's pre-check is a courtesy, the index is the guarantee) |
| Money rounding | n/a | |
| Empty/zero/null inputs | yes | empty email/password → 422 violations; empty bearer token / malformed header → 401; unknown user id on block → 404; `roles: []` normalizes to `ROLE_USER` |
| Authorization boundary | yes | `access_control` + operation-level `security`; the matrix test (anonymous / user / admin / blocked / self) covers every admin operation and `/me`; docs and health stay public |
| Deletion/expiry | yes | JWT TTL 3600 s enforced by Lexik (expired → 401, tested with a token minted with a past `exp`); no account deletion in scope |
| Idempotency of retries | yes | block/unblock idempotent (200 on repeat); registration retry after success → 422 duplicate, never a second account |

## Risks / Trade-offs

- [Lexik 3.x event names / handler configuration may differ from memory] → read `vendor/lexik/jwt-authentication-bundle/Resources/doc` of the installed version during apply; the spec fixes behavior, not the wiring.
- [API Platform `security` attribute vs `access_control` double-guard] → keep both: `access_control` is the coarse net, operation `security` the documented one; the matrix test proves the outcome.
- [Rate-limit state shared across tests] → array storage in `test`, Redis pool checked by one integration test; `RATE_LIMIT_AUTH_PER_IP` stays 10 in test so the scenario is literal.
- [Blocked-user 403 vs Symfony's default 401 for account status] → one subscriber maps `AccountStatusException` to 403; the failing-input test replays a JWT after blocking.
- [Keys missing on a fresh clone] → `make init` and CI generate them; `make check` without keys fails loudly in the token tests (documented in the how-to).
- [Trusted proxies misconfigured in prod would let clients spoof IPs] → `TRUSTED_PROXIES` defaults to `127.0.0.1` (the nginx container's view) and the spoof test asserts the untrusted case; documented in the how-to.

## Migration Plan

One additive migration (`users` + functional unique index), reversible `down()`. `make migrate` locally; CI runs `make test-db` (migrations on the test database). No data migration.
