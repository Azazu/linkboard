# Design — add-redirect-with-sync-logging

## Context

See `proposal.md` — Why. State: `links` exists with `click_count`, `max_clicks`, `expires_at`, `is_active`, `utm` and an exact-match `findBySlug`; two firewalls (`api` stateless JWT, `main` lazy session); a per-IP auth limiter on a Redis pool with a Redis lock and an in-memory storage in tests; problem-details responses for the API; `TRUSTED_PROXIES` configured; `src/Redirect/` and `src/Click/` are empty placeholders. Constraints: DataMapper entities, thin controllers, CQRS-lite (the click write path never shares entities with reads), no new dependency, the `ClickRecorder` seam must survive `add-async-click-logging` unchanged from the controller's point of view.

## Goals / Non-Goals

**Goals:** a correct, testable baseline of the redirect with an exact click limit; a write-path seam that stage 2 swaps without touching the controller or the specs' observable behavior; four small error pages; the two env variables.
**Non-Goals:** see proposal. Design-level: no Redis on the hot path yet, no caching of link rows (row 7 decides), no entity hydration for clicks.

## Decisions

1. **Route placement and firewall** — `#[Route('/{slug}', requirements: ['slug' => '[A-Za-z0-9_-]{3,32}'], methods: ['GET', 'HEAD'], priority: -100)]` on `RedirectController` (`src/Redirect/`). It stays under the `main` firewall (lazy): no `access_control` line matches `/{slug}`, so access is granted, and the controller never reads the token, so no session starts and no cookie is set (asserted by a web test). Alternative — a dedicated `security: false` firewall — rejected: its pattern would have to exclude every reserved word, duplicating `ReservedSlugs`. The lowest priority makes every attribute and YAML route win over the slug even though reserved words cannot be slugs; `debug:router` is checked in a task.
2. **Thin controller, one use case** — `RedirectController` does HTTP only: rate-limit check (decision 9), header bounds (decision 8), calls `RedirectResolver::resolve(slug, Visit)` and maps the returned `RedirectDecision` (`notFound | gone | unavailable | redirect(location)`) to a `Response`, adding `Cache-Control: no-store` to all and `Referrer-Policy` to the 302. `Visit` is a small readonly DTO (client IP, truncated UA, truncated Referer, `occurredAt`, `isHead`). `RedirectResolver` (application service): `findBySlug` (1 SELECT) → 404 when null or inactive → 410 when expired or `click_count >= max_clicks` (fast path, no write) → `HEAD`: `redirect(location)` without recording → else `ClickRecorder::record(link, visit)` → `allowed` → 302, `exhausted` → 410, failure → decision 5.
3. **Exact limit = one conditional UPDATE** — `DbalClickRecorder::record()` runs, in one DBAL transaction: `UPDATE links SET click_count = click_count + 1 WHERE id = :id AND (max_clicks IS NULL OR click_count < max_clicks)`; 0 rows → `exhausted` (no insert); 1 row → `INSERT INTO clicks (...)`; commit. The row lock taken by the UPDATE serialises concurrent requests, so the count can never pass `max_clicks` (spec redirect, "exact under concurrency"; integration test with parallel connections). It guarantees nothing when the database is unreachable — that is decision 5's job. Alternatives: `SELECT … FOR UPDATE` + separate UPDATE (two statements, longer lock), optimistic version column with retries (loops under contention) — rejected. The PHP pre-check in decision 2 is an optimisation for already-exhausted links, never the authority.
4. **DBAL write path, read-only entity** — the hot path uses `Connection` directly (no UnitOfWork, no hydration); `src/Click/Entity/Click.php` is `#[ORM\Entity(readOnly: true)]` and exists so that `doctrine:schema:validate`, `make migration` and tests know the table (§3.4 columns, `clicks_link_occurred` index, partial index `WHERE NOT is_bot`, FK `ON DELETE CASCADE`). `ClickRecorderInterface` (`src/Click/`) with `record(Link, Visit): RecordOutcome` is the seam row 7 re-implements with dispatch + Redis counter. `links.click_count` is written by SQL only; the `Link` entity keeps no setter for it (consistent with `add-link-crud` decision 1).
5. **Degradation policy** — `RedirectResolver` wraps `record()` in `try/catch (\Throwable)`: link without `max_clicks` → log `error` (`{link_id, exception: class}` — no IP, UA or URL) and return `redirect(location)`; link with `max_clicks` → log `warning` and return `unavailable` (503, `Retry-After: 5`). This is the synchronous form of FR-RED-4/FR-RED-3/NFR-REL-1 and the seam keeps it when the recorder becomes asynchronous. Not guaranteed: a crash after the commit and before the response leaves one counted click without a delivered redirect (at most one per crash). Tested by swapping the recorder for a throwing stub in the test container (`disableReboot`).
6. **UTM composition** (`src/Redirect/UtmAppender`, pure function) — `parse_url` the validated target; `parse_str` the query into an array; overwrite with the link's UTM (link wins); `http_build_query(..., PHP_QUERY_RFC3986)`; reassemble `scheme://[host[:port]]path?query#fragment`. Operates only on targets already accepted by `TargetUrlPolicy`, which rejects control characters and backslashes, so no CR/LF can reach the header; `RedirectResponse` would reject them anyway. Alternative — string concatenation `?`/`&` — rejected (breaks with fragments and duplicate keys).
7. **Visitor hash and referer host** (`src/Click/VisitorHasher`, `src/Redirect/RefererHost`) — `hash('sha256', $salt."\0".$ip."\0".$ua)` with `VISITOR_HASH_SALT` injected via `%env(VISITOR_HASH_SALT)%` (the NUL separators make the concatenation of FR-CLK-2 unambiguous; documented). `RefererHost::of(?string, string $ownHost)`: `parse_url` host, lower-cased, null when absent, unparseable or equal to the host of `APP_PUBLIC_URL` (same-origin, reusing `PublicUrl`).
8. **Header bounds** — `substr(UA, 0, 1024)`, `substr(Referer, 0, 2048)` in the controller before building `Visit`; `Accept-Language` is not read in this change. A truncated Referer that no longer parses yields `referer_host` null, never an error.
9. **Rate limiter `redirect_ip`** — `framework.rate_limiter.redirect_ip`: `sliding_window`, `limit: '%env(int:RATE_LIMIT_REDIRECT_PER_IP)%'`, `interval: '1 minute'`, `cache_pool: cache.rate_limiter`, `lock_factory: lock.factory`; `when@test` → `storage_service: app.rate_limiter.test_storage` (same reasons as `auth_ip`: pools reset between requests). Checked first thing in the controller via `#[Target('redirect_ip')]` so an over-limit client costs no SQL. Alternative — a kernel subscriber like `AuthRateLimitSubscriber` — rejected: that one exists to run before the firewall and password hashing; here the controller is the first cost. Key = `Request::getClientIp()` (trusted proxies, FR-KEY-5).
10. **Problem details helper moves to Shared** — `App\Shared\Api\ProblemDetails::response(int $status, string $title, string $detail): JsonResponse` (body and headers exactly as today's `JwtProblemDetailsSubscriber::problem`); the auth subscribers delegate to it. Content negotiation: `Accept` contains `application/json` → problem details, else Twig page (`templates/redirect/{not_found,gone,rate_limited,unavailable}.html.twig`, extending `base.html.twig`). 404/410/429/503 are returned by the controller, not thrown, so the framework's error renderer and its default headers never apply.
11. **Migration** — `make migration` after the entity mapping, then reviewed: table `clicks` per §3.4 (`id uuid PK`, `link_id uuid FK → links ON DELETE CASCADE`, `occurred_at timestamptz NOT NULL`, `country char(2)`, `device_type varchar(16)`, `os varchar(16)`, `browser varchar(32)`, `is_bot boolean NOT NULL DEFAULT false`, `referer_host varchar(255)`, `visitor_hash char(64) NOT NULL`, `variant varchar(16)`, `resolved_by varchar(8) NOT NULL`), index `(link_id, occurred_at DESC)`, partial index `(link_id, occurred_at) WHERE NOT is_bot`, `getDescription()`, reversible `down()`.
12. **Configuration** — `.env`: `RATE_LIMIT_REDIRECT_PER_IP=60`, `VISITOR_HASH_SALT=localdev-only-salt-override-in-env-local` with a comment; `.env.test`: a fixed `VISITOR_HASH_SALT`; CI: the `.env` default suffices (tests assert stability and difference, not a specific digest). The production value is referenced by name only (AGENTS.md secrets rule).

## Risks / Trade-offs

- [Hot links contend on the `links` row lock: 1 SELECT + 1 UPDATE + 1 INSERT per redirect] → accepted as the stage-1 baseline; row 7 removes the SQL write from the hot path and moves the limit to Redis; the how-to names the deviation from FR-RED-2 explicitly.
- [The committed salt default is public] → it is a local-development default like the DB password; production must set `VISITOR_HASH_SALT` in `.env.local`/CI (how-to), and a rotation note explains the lost continuity.
- [Per-IP limit penalises users behind one NAT] → default 60/min is the specification's value and is configurable; API-key limits (row 10) will not affect redirects.
- [A slug that equals a future top-level route] → `ReservedSlugs` is compared with the router by an existing test (`ReservedSlugsCoverRoutesTest`); the redirect route's `-100` priority means a new page always wins over an old slug.
- [Throwing-stub test does not exercise a real database outage] → the unit of failure is the recorder call; the integration test of the recorder covers the SQL, the web test covers the controller's reaction; a real outage differs only in the exception class.

## Migration Plan

`make migration` → review the class → `make migrate` → `make test-db`. Rollback: `doctrine:migrations:migrate prev` drops `clicks` (no data worth keeping in stage 1). Deploy order: migration, then code (the code writes to the new table).
