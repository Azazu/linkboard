# Proposal — add-routing-rules

**Risk-Tier:** high

Tier rationale (roadmap row 6, NFR-SEC-7): rule evaluation over untrusted input on the anonymous hot path (`User-Agent`, client hints, `Accept-Language`, a proxy country header, client IP); redirect-target validation extended to every rule and variant target (open-redirect and SSRF classes); two new third-party dependencies parsing attacker-controlled strings; personal data (the client IP feeds geolocation and the A/B hash). Gate 1 + Gate 2, a demonstrated failing input for every new guard, a green branch run before Gate 2 (auto review mode).

## Why

A short link today always resolves to its one `targetUrl`. The product's core promise — "smart routing": send iOS visitors to the App Store, Germans to the German site, and split the rest A/B — does not exist yet, and every click is recorded with `resolved_by = default` and null device, OS, browser, country and variant, so the analytics stage (row 8) would have nothing to report on. This change adds the routing-rules document to links, evaluates it on redirect in a fixed order, detects device/OS/browser/bot and resolves country and language, and records the outcome on the click. It is the last change before the click path becomes asynchronous (row 7), which re-implements the click write behind the existing seam without touching the evaluation.

## What Changes

1. **`rules` on the link API** (FR-LNK-1, FR-RUL-1/2/3, §4): `POST /api/v1/links` and `PATCH /api/v1/links/{id}` accept an optional `rules` JSON document (version 1: up to 20 `rules`, each with exactly one dimension in `match` — `device` and `os` together count as the device dimension — non-empty value arrays from the fixed vocabularies; 2–4 `variants` with distinct names and integer weights summing to 100; every `target` under the existing target URL policy). Invalid documents answer 422 with one `violations` entry per violation, its `propertyPath` naming the offending element (`rules[rules][0][match][device][1]`, `rules[variants][1][weight]`). Merge-patch contract: `rules` present replaces the whole document, `rules: null` clears it, absent leaves it unchanged. Every link response carries `rules` (the stored document or null). The document schema is published as JSON Schema in `docs/reference/rules-schema.json`; the PHP validator has the same structure and a test keeps the two in step.
2. **Evaluation on redirect** (FR-RUL-4/5): the `Location` of a 302 becomes the resolved destination with the link's UTM appended. Order, fixed and explicit: device-dimension rules in document order → country rules → language rules → A/B variants → `targetUrl`; the first match wins; a rule whose dimension could not be resolved for this visitor (unknown device, unknown country, no usable `Accept-Language`) is skipped, never matched. The A/B variant is deterministic per visitor without cookies: `crc32(link_id ‖ client_ip ‖ user_agent) mod 100` against the cumulative weights.
3. **Detection and resolution** (FR-RUL-6): device type, OS, browser and bot flag from `matomo/device-detector` over the bounded `User-Agent` and client hints, mapped onto the specification's vocabularies (`desktop | smartphone | tablet | other`, `iOS | Android | Windows | macOS | Linux | other`); country through a `CountryResolver` chain whose members and order are configuration (`COUNTRY_RESOLVERS`): a proxy header (`GEOIP_COUNTRY_HEADER`, default `CF-IPCountry`, honoured only when the request comes from a trusted proxy) and GeoLite2 (`geoip2/geoip2`, database file at `GEOIP_DATABASE_PATH`, not committed; the resolver disables itself with one `warning` when the file is missing); language as the primary ISO 639-1 subtag of the highest-quality `Accept-Language` entry. Tests use a fixed IP→country map.
4. **Hostile-input degradation** (FR-RUL-7, NFR-SEC-4): `Accept-Language` bounded to 256 bytes and each client-hint header to 256 bytes before parsing (the `User-Agent` bound of 1024 bytes exists); an unparseable value is an unresolved dimension, not an error; any exception during detection, geolocation or evaluation degrades the request to the link's `targetUrl` with `resolved_by = default` and one `notice` log record carrying the link id and the exception class — never the IP or user agent. A malformed 8 KB `Accept-Language` or a garbage `User-Agent` is a 302.
5. **Click record completed** (§3.4, FR-CLK-2/6): the synchronous recorder now stores `country`, `device_type`, `os`, `browser`, `is_bot`, `resolved_by` (`device | country | language | variant | default`) and `variant` for every click; the raw IP and user agent are still never persisted. Bots are stored (excluded from reports by the analytics change).
6. **Configuration**: `COUNTRY_RESOLVERS=header,geolite2`, `GEOIP_COUNTRY_HEADER=CF-IPCountry`, `GEOIP_DATABASE_PATH=%kernel.project_dir%/var/geoip/GeoLite2-Country.mmdb` in `.env` (no secrets; `var/` is gitignored), `COUNTRY_RESOLVERS=fixed` in `.env.test`; a filesystem cache pool for the device-detector regex database so the hot path gains no Redis dependency.
7. **Dependencies** (anti-overengineering rule, §5): `matomo/device-detector` — the maintained open user-agent database; hand-written regexes are wrong within months and nothing installed parses user agents. `geoip2/geoip2` — the reader for the offline GeoLite2 database, the only license-free-for-development IP→country source; nothing installed does geolocation, the resolver interface keeps it swappable, and its transitive HTTP client (`maxmind/web-service-common`) is never used. No JSON Schema validation library: the PHP validator is the runtime authority and the schema file is documentation kept in step by a parity test; a library would add a dependency to validate a 20-rule document.
8. **Tests** (exit criterion of §7 row 6): unit — document validation (an accepted fixture and one rejected fixture per constraint, each with its violation path), schema parity, evaluation matrix device × country × language × variants × default plus skipped-dimension cases, A/B determinism and distribution (10 000 synthetic visitors within ±3 % of the weights), language parsing, country chain (trusted-proxy header, missing GeoLite2 file, reader failure), detector mapping over fixed user-agent strings; API — `rules` round trip, every 422 class over HTTP, merge-patch null contract; web — the matrix over HTTP with real detection (fixed user agents, mapped IPs, `Accept-Language`), the click row carrying the resolution, hostile inputs (garbage UA, 8 KB `Accept-Language`, spoofed country header from an untrusted peer), a throwing detector → 302 default with a `notice`.
9. **Docs**: `docs/reference/rules-schema.json`; a "Routing rules" section in the how-to (a `curl` that creates a link with rules, how to test a rule with `-A` and `Accept-Language`, GeoLite2 download and the three variables, the trusted-proxy condition of the header resolver); roadmap row 6 and requirements §7 row 6 re-read against the delivered scope.

## Capabilities

### New Capabilities

- `routing-rules`: the routing-rules document (shape, vocabularies, limits, target policy, violation paths) and its evaluation on redirect (fixed order, skipped dimensions, deterministic A/B, device/OS/bot detection, country and language resolution, degradation on hostile input).

### Modified Capabilities

- `links`: "Create a link with a generated or custom slug" gains the optional `rules` field in the request and `rules` in every link response; "Update a link" gains `rules` in the merge-patch null contract (present replaces, null clears, absent unchanged).
- `redirect`: "Destination with UTM appended" — `Location` is the destination resolved by the routing rules (a rule target, a variant target or `targetUrl`) with UTM appended; the matrix, headers, limit and failure contract are unchanged.
- `click-logging`: "Click record contents" — `country`, `device_type`, `os`, `browser`, `is_bot`, `resolved_by` and `variant` are now populated from detection, resolution and evaluation; the personal-data rules are unchanged.

## Non-goals

- Asynchronous click logging, the Redis click counter, retries and the failed transport (`add-async-click-logging`, row 7); the recorder keeps writing synchronously behind `ClickRecorderInterface`, which gains the click facts as a parameter.
- Analytics reports over the new columns, the `variants` report, the bots toggle (`add-analytics-read-model`, row 8).
- A rules editor in the web UI (`add-web-ui`, row 11); OpenAPI examples beyond a field description (`polish-api-and-openapi`, row 12).
- Per-rule A/B variants, scheduled rules, weighted geo fallbacks, IP allow/deny lists, region or city resolution, cookie-based sticky variants (§10).
- Shipping a GeoLite2 database or any geo data in the repository or the image; a download automation (`make` target or cron) — the how-to documents the manual download.
- Performance measurement of the hot path (NFR-PERF-1) — measured once the click path is final (row 7).
- A database migration: `links.rules` (JSONB) and every `clicks` column already exist.
