# Design — add-routing-rules

## Context

See `proposal.md` — Why. State: `links.rules` is a nullable JSONB column mapped on `Link` (`getRules()`, no writer); every `clicks` column of §3.4 exists and the synchronous `DbalClickRecorder` writes null/`default` into the seven columns this change fills; `RedirectResolver` orders lookup → 404 → 410 → HEAD → `record()` → 302/410/503 and wraps the write in its failure policy; `UtmAppender` is a pure function over any target; `TargetUrlPolicy::isAllowed()` is a pure function; `Visit` carries the bounded `User-Agent`/`Referer`, the client IP and `isHead`; `UpdateLinkProcessor` already reads the raw request body to know which keys are present; `TRUSTED_PROXIES=127.0.0.1`; the serializer decodes request bodies associatively (`JsonEncoder` → `JsonDecode::ASSOCIATIVE`), so a `mixed` DTO property cannot tell a JSON object from a JSON array; `App\Kernel` uses `MicroKernelTrait` over `HttpKernel\Kernel` whose `boot()` is public and overridable; `symfony/yaml`, `symfony/cache` and `symfony/validator` are installed, `symfony/intl` is not. Constraints: DataMapper entities, thin controllers, CQRS-lite, Click must not depend on Redirect, the recorder seam must stay the one place `add-async-click-logging` re-implements, no Redis on the hot path beyond the fail-open limiter, level-8 PHPStan.

## Goals / Non-Goals

**Goals:** one authority for the document's shape shared by validation and evaluation, reading JSON types faithfully; a pure, fully unit-testable evaluation order; a single explicit policy for absent, unrecognised, hostile and throwing input that matches FR-RUL-4 and FR-RUL-7; detection and geolocation that cannot fail a redirect or leak personal data; configuration-selected country resolvers validated at boot; the click row complete for the analytics stage.
**Non-Goals:** see proposal. Design-level: no typed rules entity or separate table (JSONB as specified, never queried by content); no caching of detection results per visitor; no `symfony/intl` for country/language codes (format checks by regex — the specification defines formats, not membership in an assigned-code list); no JSON Schema validation library; no compile-time validation of `COUNTRY_RESOLVERS` (it is a runtime environment variable; the boot check is the mechanism).

## Decisions

1. **One parser over a type-preserving JSON tree, two consumers** — `App\Link\Rules\RulesDocumentParser::parse(mixed $node): ParseResult` walks a decoded JSON tree in which objects are `\stdClass` and arrays are PHP lists — the shape `json_decode($json, false)` produces — and returns either a typed, immutable `RulesDocument` (`list<Rule>` with `Dimension` enum `Device|Country|Language`, device values, OS values, `list<Variant>`) or a `list<RuleViolation>` of `(path, message)` with paths in array-access notation (`[rules][0][match][device][1]`). Type tests are strict: an object is `\stdClass` (or, for stored documents, a non-empty PHP array with string keys — see below), a list is a PHP array for which `array_is_list()` holds, an integer is `is_int()` (so `50.0` and `"50"` fail), a string is `is_string()`. A JSON object where an array is required — `{"0": …}` included — is therefore a violation at that position, and `{}` at the root is a `\stdClass` without `version` and without `rules`/`variants`, reported as the single root violation. On the hot path the evaluator hands the parser the **stored** array (decision 2 stores the canonical `RulesDocument::toArray()` form: objects as string-keyed arrays, arrays as lists, none of them empty by the document's own limits), so `array_is_list()` separates the two kinds without ambiguity; any deviation (a hand-edited row, a future format) yields violations and is an *anomaly* handled by decision 5. Limits and vocabularies are constants on `RulesDocument` (`MAX_RULES = 20`, `MIN_VARIANTS = 2`, `MAX_VARIANTS = 4`, `MAX_VALUES = 64`, `WEIGHT_SUM = 100`, `MIN_WEIGHT = 1`, `NAME_PATTERN`, `COUNTRY_PATTERN`, `LANGUAGE_PATTERN`, `DEVICES`, `OSES`) — the single source the JSON Schema file and its parity test read. Targets are checked with `TargetUrlPolicy::isAllowed()` and `TargetUrl::MAX_LENGTH`; a failing target is a violation at `[rules][i][target]` / `[variants][i][target]`. Alternatives rejected: nested `Assert\Collection`/`Assert\All` constraints (cannot express "exactly one dimension", the weight sum or distinct names without callbacks; would leave the evaluator with a second, implicit reading of the shape; operate on the associative decode and so cannot see JSON types); a JSON Schema library as the runtime validator (proposal §7); parsing only the serializer's associative array (loses the object/array distinction the schema promises — Gate 1 finding 1).
2. **`rules` is read from the raw request body; the DTO property is a placeholder** — `App\Link\Api\RulesInput::fromRequest(Request): RulesInput` decodes the raw body once with `json_decode($content, false, 512, JSON_THROW_ON_ERROR)` (objects preserved; a non-object body is already the 400 of the existing presence check) and exposes `present: bool` and `node: mixed` for the `rules` member. Both consumers use it: the constraint `#[App\Link\Validator\RulesDocument]` on `CreateLinkInput::$rules` / `UpdateLinkInput::$rules` (declared `mixed`, default null, so the serializer accepts any JSON there and OpenAPI shows the field; its decoded value is never read) obtains the current request through `RequestStack`, parses `node` and emits each violation with `atPath()`, so the API path is `rules` + the parser path (`rules[rules][0][match]`, consistent with the existing `utm[utm_foo]` style); `null` or absent → nothing to validate; a `node` that is neither `\stdClass` nor null (a string, number, boolean, or a PHP list — JSON `[]`) → one violation at `rules`. The processors call `RulesInput` again (cheap: one decode of a body that is at most a few KB), parse, and persist `RulesDocument::toArray()` — the canonical form (`version`, `rules`, `variants` in that member order; `match` members in the order `device`, `os`, `country`, `language`; `name`, `weight`, `target`). `Link::replaceRules(?array $canonical, \DateTimeImmutable $now)` stores it; `CreateLinkProcessor` calls it when the document is present and non-null; `UpdateLinkProcessor` calls it when `present` (null clears, a document replaces the whole stored one — merge-patch semantics stop at the field, stated in spec links). `LinkResource` gains `public ?array $rules` (the stored canonical form; JSON-value-equal to what was posted) with an `ApiProperty` description pointing at `docs/reference/rules-schema.json` (OpenAPI polish is row 12). Guarantee: no request can store a document the parser did not accept from the type-preserving tree; not guaranteed: a document written to the column by other means (decision 5 covers it at read time).
3. **Published schema + parity test** — `docs/reference/rules-schema.json` is a JSON Schema 2020-12 document (`$id`, `additionalProperties: false` at every object, `type` on every member — `array` for `rules`, `variants` and every value list, `object` for the document, each rule, `match` and each variant, `integer` for `version` and `weight`, `string` for names, values and targets — `enum` for device/OS, `pattern` for country/language/name, `minItems`/`maxItems`, `const: 1` for `version`, `minimum: 1` for weight, `oneOf` over the three dimension shapes with the device shape allowing `device`, `os` or both, `anyOf` requiring `rules` or `variants`). The weight sum is documented in `description` (JSON Schema cannot express it). `RulesSchemaParityTest` decodes the file and asserts each enumeration, limit, pattern and `type` equals the `RulesDocument` constant or the parser's type test, that every object schema has `additionalProperties: false`, and that the how-to example document parses without violations. Guarantee: the file cannot drift from the validator on any value the test reads; it does not guarantee that the schema's structural composition (`oneOf`) is exactly equivalent to the parser — that is reviewed by eye and covered by the shared fixtures.
4. **`Visit` grows and classifies its inputs; `VisitFactory` builds it** — `App\Click\Visit` gains `acceptLanguage` (`?string`, only when well-formed), `clientHints` (`array<string,string>`, only header names starting with `Sec-CH-UA`, only well-formed values), `proxyCountry` (`?string`, the header named by `GEOIP_COUNTRY_HEADER`, only when `Request::isFromTrustedProxy()` is true and the value is well-formed) and `inputIssues` (`list<string>`, empty for a clean request). `App\Redirect\VisitFactory::fromRequest(Request, \DateTimeImmutable, bool $isHead): Visit` owns the classification (NFR-SEC-4, FR-RUL-7): each header is *absent*, *well-formed* or *hostile*; hostile means `User-Agent` over 1024 bytes, not valid UTF-8 or containing a control character (`[\x00-\x1F\x7F]`); `Accept-Language` over 256 bytes or not matching the grammar `^\s*[A-Za-z0-9*]+(-[A-Za-z0-9]+)*\s*(;\s*q\s*=\s*(0(\.\d{1,3})?|1(\.0{1,3})?)\s*)?(,\s*[A-Za-z0-9*]+(-[A-Za-z0-9]+)*\s*(;\s*q\s*=\s*(0(\.\d{1,3})?|1(\.0{1,3})?)\s*)?)*$`; a `Sec-CH-UA*` header over 256 bytes or with a control character; a trusted proxy's country header over 16 bytes or with a control character. A hostile header is not carried (the field stays null / the hint is dropped) and its issue class — `user_agent_oversized`, `user_agent_malformed`, `accept_language_oversized`, `accept_language_malformed`, `client_hints_oversized`, `client_hints_malformed`, `proxy_country_malformed` — is appended to `inputIssues`. Independently of classification, `userAgent` is always the header cut to 1024 bytes (the visitor hash and the click's oversized-UA scenario of spec click-logging keep working) and `referer` is cut to 2048 bytes as before. The trust decision for the country header is made here so the resolver needs no `Request` and the property "an untrusted peer can never supply a country" is one line with one failing input (remove the condition → the spoof test fails). `Visit::fromHeaders` is removed (its callers are tests) — verified by `rg`.
5. **Profile → evaluate → facts, inside one guard, with hostile input short-circuited** — `App\Redirect\VisitorProfiler::profile(Visit): VisitorProfile` (deviceType, os, browser, isBot, country, language) runs `DeviceDetection` (decision 7), the `CountryResolverInterface` chain (decision 8) and `AcceptLanguage` (decision 9); each returns null for absent or unrecognised input. `App\Redirect\Rules\RuleEvaluator::evaluate(?array $storedRules, VisitorProfile, Visit, Uuid $linkId, string $targetUrl): Resolution` parses the document (decision 1) and applies the fixed order: rules grouped by dimension in the order device → country → language, each group in document order, a rule matching when every listed value list contains the profile's value (a null profile value for a listed dimension = skip, FR-RUL-4); then `VariantPicker` (decision 10) if variants exist; else default. `Resolution` = `(target, ResolvedBy enum, ?variant)`. `RedirectResolver`, after the 410 fast path and before HEAD/record: if `$visit->inputIssues !== []` → `notice('Routing degraded to the default target', ['link_id', 'issues' => $visit->inputIssues])`, `$profile = VisitorProfile::unknown()`, `$resolution = Resolution::default($link->getTargetUrl())` — detection, geolocation and evaluation are **not attempted** on hostile bytes (FR-RUL-7); otherwise `try { $profile = …; $resolution = …; } catch (\Throwable $e) { notice(…, ['link_id', 'exception' => $e::class]); same defaults }`. Then `location = UtmAppender::append($resolution->target, utm)`, `HEAD` → redirect without recording, else `record($link, $visit, ClickFacts::from($profile, $resolution))`. Three input classes, one policy each: absent/unrecognised → skipped dimension, no log (FR-RUL-4); hostile → default target + one `notice` with issue classes, no values (FR-RUL-7); throwing or unusable document → default target + one `notice` with the exception class. The guard guarantees a 302 for every throwable inside the three steps and for every hostile request; it does not guarantee that a bug is noticed by anything but the `notice` line (the exception class is logged; PHPStan and the unit matrix keep the evaluator honest). Alternative — treat hostile input as a skipped dimension — rejected: FR-RUL-7 requires the default target and a `notice`, and a matching language rule would otherwise be selectable by an 8 KB header (Gate 1 finding 3). Alternative — evaluate inside the recorder or the controller — rejected: the resolver already owns the decision order and the failure policies; the controller stays HTTP-only.
6. **Anomalous stored documents** — `RuleEvaluator` throws `App\Redirect\Rules\UnusableRulesException` when the parser reports violations for a stored document; the guard of decision 5 turns it into the default target plus one `notice`. No repair, no migration of documents: none exist before this change.
7. **Device detection** (`App\Redirect\Detection\DeviceDetection::detect(Visit): DetectedClient`) — `matomo/device-detector ^6.5`: a `DeviceDetector` per request over `Visit::$userAgent` (already well-formed when this runs — hostile requests never reach it, decision 5) and `ClientHints::factory()` built from `Visit::$clientHints`; `setCache(new PSR6Bridge($pool))` with the pool `cache.device_detector` (filesystem adapter, `config/packages/cache.yaml`) so the regex database is parsed once per deploy on local disk — no Redis, no network; `setYamlParser(new Yaml\Symfony())` to use the installed `symfony/yaml`; `skipBotDetection(false)`, `discardBotInformation(true)` (a bot yields `isBot = true` and null device/OS). Mapping onto the vocabularies: device name `desktop` → `desktop`, `smartphone` and `phablet` → `smartphone`, `tablet` → `tablet`, any other non-empty name → `other`, empty → null; OS via the library's OS family: `iOS` → `iOS` (iPadOS is in that family), `Android` → `Android`, `Windows` → `Windows`, `Mac` → `macOS`, `GNU/Linux` → `Linux`, any other non-empty family → `other`, unknown → null; browser = client name when the client type is `browser`, `mb_substr(…, 0, 32)`, else null. The class names, the family table and the client-hint factory signature are verified against `vendor/` in task 1.1 before the wrapper is written; the mapping is asserted on fixed user-agent strings in a unit test, so a library update that reclassifies a fixture fails a test rather than a rule. Bots are evaluated like any visitor (they usually have null dimensions and fall to the variants or the default); the analytics stage excludes them.
8. **Country resolver chain, validated at every boot** — `App\Redirect\Geo\CountryResolverInterface::resolve(Visit): ?string` (upper-case alpha-2 or null). Implementations are tagged `app.country_resolver` with a `key`; `ChainCountryResolver` receives them by `#[AutowireIterator('app.country_resolver', indexAttribute: 'key')]` plus `COUNTRY_RESOLVERS` and, in its constructor, resolves the comma-separated names to instances; an unknown name throws `\InvalidArgumentException` naming it and the known keys. Symfony instantiates services on demand and `debug:container` describes definitions without instantiating them, so the constructor alone would surface a typo only when the redirect controller's dependencies are built — a 500 on the first redirect, outside the guard (Gate 1 finding 2). The boot mechanism is therefore explicit: `App\Kernel::boot()` is overridden to call `parent::boot()` and then `$this->container->get(App\Shared\Boot\StartupChecks::class)->run()`; `StartupChecks` is a small public service (`public: true` in `services.yaml`) holding an `iterable` of `StartupCheckInterface` implementations tagged `app.startup_check`, and `ChainCountryResolver` implements that interface (its `check()` is a no-op — construction already validated the names, so merely being instantiated by `StartupChecks` is the check). Every kernel boot — web request, console command, worker, `KernelTestCase` — constructs the chain before anything is served, and a bad `COUNTRY_RESOLVERS` fails the boot with the exception message. Env parameters are resolved at runtime from `$_SERVER`/`$_ENV`, so the check does not depend on the container cache being rebuilt (a cache warmer would run only at container build and miss an env change; rejected as the primary mechanism). Verified by an integration test that sets `$_SERVER['COUNTRY_RESOLVERS'] = 'bogus'` before `bootKernel()` and expects the exception, then boots with `fixed` and obtains the chain, and by `docker compose exec -T -e COUNTRY_RESOLVERS=bogus php bin/console about` exiting non-zero (task 3.4). `HeaderCountryResolver` (`header`): returns `strtoupper(Visit::$proxyCountry)` when it matches `^[A-Za-z]{2}$` and is not `XX`/`T1` (Cloudflare's unknown/Tor markers), else null — trust was already decided in decision 4. `GeoLite2CountryResolver` (`geolite2`): `geoip2/geoip2 ^3.4`; the `Reader` is created lazily on first use through an injected factory closure (the test seam) from `GEOIP_DATABASE_PATH` (`%env(resolve:…)%`, default `%kernel.project_dir%/var/geoip/GeoLite2-Country.mmdb`); if the file is missing or the reader cannot open it, the resolver sets a `disabled` flag, logs one `warning` (`{path_configured: true}` — no path value needed, it is configuration) and returns null for the rest of the process; `AddressNotFoundException` (private, reserved or unknown addresses) → null silently; any other `\Throwable` from a lookup → null and a `notice` `{exception: class}` without the IP. `FixedMapCountryResolver` (`fixed`, `tests/Fixture/`, registered under `when@test` in `config/services.yaml`): constant map `198.51.100.7 → DE`, `198.51.100.44 → US`, `198.51.100.33 → FR`, everything else null — the default test peer `203.0.113.7` stays unmapped so existing click tests are unaffected. Defaults: `.env` `COUNTRY_RESOLVERS=header,geolite2` (the header is free; the database is a file read), `.env.test` `COUNTRY_RESOLVERS=fixed`. Guarantee boundary: geolocation is best-effort; a wrong or missing answer is an unknown country and a skipped rule, never an error or a leaked IP. Not tested against a real GeoLite2 file (the database is licensed and not committed): the reader's behaviour is covered through the factory seam with a stub reader, and the how-to documents the manual check with a downloaded database.
9. **Language** — `App\Redirect\Language\AcceptLanguage::primary(?string $header): ?string` receives only a well-formed header (decision 4 has already rejected oversized or out-of-grammar values as hostile) and parses it with `Symfony\Component\HttpFoundation\AcceptHeader::fromString()->all()` (sorted by quality, verified in `vendor/`); the first item's value is split at `-`/`_`, lower-cased, accepted only when it matches `^[a-z]{2}$`; `*`, `x`, `zh-Hant-TW` → null, null, `zh`. Absent → null. The request's own `getLanguages()` is not used: it parses the unbounded header and returns invalid values as is.
10. **A/B assignment** — `App\Redirect\Rules\VariantPicker::pick(list<Variant>, Uuid $linkId, string $clientIp, string $userAgent): Variant` computes `crc32($linkId->toRfc4122()."\0".$clientIp."\0".$userAgent) % 100` (NUL separators make the concatenation of FR-RUL-5 unambiguous, as the visitor hash does) and walks the cumulative weights in document order (`value < cumulative` → that variant). CRC32 is the specification's formula and a distribution function, not a security primitive; the salted SHA-256 `visitor_hash` remains the identity at rest. Determinism holds while IP and user agent are unchanged (stated); the distribution property is asserted over 10 000 synthetic distinct visitors within ±3 percentage points for weights 70/30 (a `% 2` regression fails it). When the client IP is unknown (`''`) the formula still yields a deterministic value.
11. **Click facts through the seam** — `App\Click\ClickFacts` (readonly: `?country`, `?deviceType`, `?os`, `?browser`, `bool isBot`, `string resolvedBy`, `?variant`) with `ClickFacts::default()`; `ClickRecorderInterface::record(Link $link, Visit $visit, ClickFacts $facts): RecordOutcome`; `DbalClickRecorder` writes the seven columns from it (the transaction, the conditional UPDATE and the failure policy are unchanged). `ClickFacts::from(VisitorProfile, Resolution)` lives in Redirect (Click does not know Redirect types). Column fit is guaranteed by construction: `variant` ≤ 16 by the name pattern, `resolved_by` ≤ 8 (`language` is 8), `device_type`/`os` from fixed vocabularies ≤ 16, `browser` cut to 32, `country` 2 letters. Row 7 re-implements the same signature with a message carrying the facts.
12. **Configuration and dependencies** — `.env`: `COUNTRY_RESOLVERS=header,geolite2`, `GEOIP_COUNTRY_HEADER=CF-IPCountry`, `GEOIP_DATABASE_PATH=%kernel.project_dir%/var/geoip/GeoLite2-Country.mmdb` with comments (the file is downloaded by the operator, never committed — `var/` is gitignored); `.env.test`: `COUNTRY_RESOLVERS=fixed`. `composer.json`: `matomo/device-detector: ^6.5`, `geoip2/geoip2: ^3.4` (both require PHP ≥ 8.1; transitive `mustangostang/spyc`, `maxmind-db/reader`, `maxmind/web-service-common`); `composer audit` runs in the task; the lock diff is reviewed and the commit is flagged **security-sensitive: dependencies**. No migration.

## Applicability (high tier)

| Question | Applies? | Note |
|---|---|---|
| Crash before/after an external effect | n/a | no new external effect: the click transaction of the previous change is unchanged; detection reads a local cache, GeoLite2 reads a local file; the `notice` of the guard is written after the outcome is known |
| Concurrent writers | n/a | evaluation is pure and per request; no new write; the conditional UPDATE keeps the limit exact (previous change, decision 3) |
| Money rounding | n/a | |
| Empty/zero/null inputs | yes | `rules` null/absent/`[]`/`{}`/scalar and JSON objects where arrays are required (decisions 1–2); empty value arrays, weight 0, `50.0`, one or five variants, `{"version":1}` alone (decision 1); missing or unrecognised `User-Agent`/`Accept-Language`/client hints → null dimensions, skipped rules, no log; oversized or malformed ones → hostile, default target, one `notice` (decisions 4–5); unknown client IP `''` → deterministic variant, no country; a document with rules that all skip and no variants → default; `COUNTRY_RESOLVERS` empty or unknown → boot failure (decision 8) |
| Authorization boundary | yes | `rules` is written only through operations already guarded by `LINK_EDIT`/`ROLE_USER`; every rule and variant target passes `TargetUrlPolicy`, so a rule cannot open a destination class the plain target could not (open-redirect/SSRF surface unchanged); the country header is honoured only from `TRUSTED_PROXIES` (decision 4, failing input: remove the condition); hostile bytes never reach the two parsing libraries (decision 5); the redirect stays public and reads no token |
| Deletion/expiry | n/a | unchanged: clicks cascade with the link; expiry precedes evaluation in the resolver |
| Idempotency of retries | n/a | a client retry is a new visit; the deterministic variant makes a retried visitor consistent by construction (decision 10); no new write |

## Risks / Trade-offs

- [Device detection on the hot path costs CPU (regex database)] → PSR-6 filesystem cache warms once per deploy; no network or Redis; the p95 target (NFR-PERF-1) is measured in row 7 once the click write leaves the request; the how-to states that the first requests after a deploy are slower.
- [Library classification drifts with updates] → fixtures of real user agents assert the mapping; an update that reclassifies a fixture fails `make check`, and the mapping table is the one place to adjust.
- [GeoLite2 is licensed and not shipped] → the resolver disables itself with one `warning`; local and CI runs use `header,geolite2` with no file (dev) or the fixed map (test); the how-to documents the download; the header resolver covers Cloudflare-style deployments without any file.
- [A spoofable country header] → honoured only from a trusted proxy (decision 4); tested from an untrusted peer and from `127.0.0.1`.
- [A typo in `COUNTRY_RESOLVERS` breaks every redirect] → intended fail-fast: every boot fails with a message naming the typo (decision 8); tested by booting the test kernel with `bogus`; the console command in the how-to shows the failure before a deploy serves traffic.
- [`mixed $rules` bypasses the serializer's type checks and the DTO value is unused] → the constraint over the raw, type-preserving decode is the sole authority (decision 2) and every violation class, including JSON objects where arrays are required, has an HTTP test; the processors use the same raw decode, so what was validated is what is stored.
- [The raw body is decoded twice (presence check / rules input, plus the serializer)] → bodies are small (a 20-rule document is a few KB) and the existing presence check already does this; a single `RulesInput` per request could be memoised later if profiling shows a cost.
- [Schema file and validator disagree] → parity test on every constant and type; shared example fixture.
- [The hostile-input policy sends real visitors with odd browsers to the default target] → only oversized or grammatically malformed headers are hostile; unrecognised but well-formed agents are skipped dimensions (decision 4); the `notice` lists issue classes so a false positive is visible in logs.
- [A catch-all guard hides evaluation bugs] → the `notice` names the exception class and the link id; the evaluator has a unit matrix and PHPStan level 8; the guard is the specification's requirement (FR-RUL-7), not a convenience.
- [CRC32 modulo 100 is coarse for tiny weights] → weights are integers 1–99 by construction and the distribution test bounds the error at ±3 pp for 10 000 visitors; per-visitor stickiness, not statistical perfection, is the requirement.
- [The recorder signature changes] → intended: the seam gains the facts that row 7's message must carry; all three implementations/callers (recorder, resolver, tests) change in this change; `rg 'record\('` closes the set.
- [Two new dependencies parse attacker-controlled bytes] → both are widely deployed; hostile bytes never reach them (decision 5) and well-formed inputs are bounded; the guard turns any exception into the default target; `composer audit` in the task and the commit flagged as security-sensitive.

## Migration Plan

No database migration. Deploy: `composer install` (two packages), code, then optionally place the GeoLite2 file at `GEOIP_DATABASE_PATH` — the resolver picks it up on the next process start (lazy reader, one attempt per process). A wrong `COUNTRY_RESOLVERS` fails the first `bin/console` of the deploy (decision 8). Rollback: revert the code; stored documents in `links.rules` are ignored by the previous resolver (it never read the column) and after a rollback the field simply disappears from responses.
