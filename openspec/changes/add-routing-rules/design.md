# Design — add-routing-rules

## Context

See `proposal.md` — Why. State: `links.rules` is a nullable JSONB column mapped on `Link` (`getRules()`, no writer); every `clicks` column of §3.4 exists and the synchronous `DbalClickRecorder` writes null/`default` into the seven columns this change fills; `RedirectResolver` orders lookup → 404 → 410 → HEAD → `record()` → 302/410/503 and wraps the write in its failure policy; `UtmAppender` is a pure function over any target; `TargetUrlPolicy::isAllowed()` is a pure function; `Visit` carries the bounded `User-Agent`/`Referer`, the client IP and `isHead`; `TRUSTED_PROXIES=127.0.0.1`; `symfony/yaml`, `symfony/cache` and `symfony/validator` are installed, `symfony/intl` is not. Constraints: DataMapper entities, thin controllers, CQRS-lite, Click must not depend on Redirect, the recorder seam must stay the one place `add-async-click-logging` re-implements, no Redis on the hot path beyond the fail-open limiter, level-8 PHPStan.

## Goals / Non-Goals

**Goals:** one authority for the document's shape shared by validation and evaluation; a pure, fully unit-testable evaluation order; detection and geolocation that cannot fail a redirect or leak personal data; configuration-selected country resolvers; the click row complete for the analytics stage.
**Non-Goals:** see proposal. Design-level: no typed rules entity or separate table (JSONB as specified, never queried by content); no normalisation of the stored document beyond validation; no caching of detection results per visitor; no `symfony/intl` for country/language codes (format checks by regex — the specification defines formats, not membership in an assigned-code list); no JSON Schema validation library.

## Decisions

1. **One parser, two consumers** — `App\Link\Rules\RulesDocumentParser::parse(mixed $input): ParseResult` walks the raw decoded JSON once and returns either a typed, immutable `RulesDocument` (`list<Rule>` with `Dimension` enum `Device|Country|Language`, device values, OS values, `list<Variant>`) or a `list<RuleViolation>` of `(path, message)` with paths in array-access notation (`[rules][0][match][device][1]`). The Symfony constraint `#[App\Link\Validator\RulesDocument]` on the inputs' `mixed $rules` delegates to the parser and emits each violation with `atPath()`, so the API path is `rules` + the parser path (`rules[rules][0][match]`), consistent with the existing `utm[utm_foo]` style. On the hot path the evaluator parses the stored array with the same parser; a stored document that yields violations (impossible for documents written by this code, possible after a manual DB edit or a future format change) is an *anomaly* handled by decision 6. Alternative — nested `Assert\Collection`/`Assert\All` constraints — rejected: they cannot express "exactly one dimension", "weights sum to 100" or "distinct names" without custom callbacks, they would leave the evaluator with a second, implicit reading of the shape, and their paths are harder to keep in step with the schema file. Alternative — a JSON Schema library as the runtime validator — rejected (proposal §7). Limits and vocabularies are constants on `RulesDocument` (`MAX_RULES = 20`, `MIN_VARIANTS = 2`, `MAX_VARIANTS = 4`, `MAX_VALUES = 64`, `WEIGHT_SUM = 100`, `MIN_WEIGHT = 1`, `NAME_PATTERN`, `COUNTRY_PATTERN`, `LANGUAGE_PATTERN`, `DEVICES`, `OSES`) — the single source the JSON Schema file and its parity test read. Targets are checked with `TargetUrlPolicy::isAllowed()` and `TargetUrl::MAX_LENGTH`; a failing target is a violation at `[rules][i][target]` / `[variants][i][target]`.
2. **`rules` on the API is `mixed`** — `CreateLinkInput::$rules` and `UpdateLinkInput::$rules` are untyped (`mixed`, default null) so the serializer never rejects a scalar or list with its own error shape; the constraint is the only judge and answers 422 on `rules` for anything that is not an object or null (spec routing-rules, "Rules document shape"); a decoded empty array — JSON `[]` and `{}` are indistinguishable after `json_decode(…, true)` — is treated as "not an object" and is that same single violation. `Link::replaceRules(?array $rules, \DateTimeImmutable $now)` stores the decoded array as validated (JSONB; no re-ordering, no defaults filled in) — what the client sent is what `GET` returns. `CreateLinkProcessor` calls it when non-null; `UpdateLinkProcessor` calls it when the key is present (null clears, a document replaces the whole stored one — merge-patch semantics stop at the field, stated in spec links). `LinkResource` gains `public ?array $rules` with an `ApiProperty` description pointing at `docs/reference/rules-schema.json` (OpenAPI polish is row 12).
3. **Published schema + parity test** — `docs/reference/rules-schema.json` is a JSON Schema 2020-12 document (`$id`, `additionalProperties: false` at every object, `enum` for device/OS, `pattern` for country/language/name, `minItems`/`maxItems`, `const: 1` for `version`, `minimum: 1` for weight, `oneOf` over the three dimension shapes with the device shape allowing `device`, `os` or both, `anyOf` requiring `rules` or `variants`). The weight sum is documented in `description` (JSON Schema cannot express it). `RulesSchemaParityTest` decodes the file and asserts each enumeration, limit and pattern equals the `RulesDocument` constant, that every object schema has `additionalProperties: false`, and that the how-to example document parses without violations. Guarantee: the file cannot drift from the validator on any value the test reads; it does not guarantee that the schema's structural composition (`oneOf`) is exactly equivalent to the parser — that is reviewed by eye and covered by the shared fixtures.
4. **`Visit` grows, `VisitFactory` builds it** — `App\Click\Visit` gains `acceptLanguage` (≤ 256 bytes), `clientHints` (`array<string,string>`, only header names starting with `Sec-CH-UA`, each value ≤ 256 bytes) and `proxyCountry` (`?string`, the raw value of the header named by `GEOIP_COUNTRY_HEADER` cut to 16 bytes, set **only** when `Request::isFromTrustedProxy()` is true, otherwise null). `App\Redirect\VisitFactory::fromRequest(Request, \DateTimeImmutable, bool $isHead): Visit` owns the bounds (NFR-SEC-4) and the header name from the environment; the controller shrinks to `factory->fromRequest(...)`. Trust decision here rather than in the resolver: the resolver then needs no `Request`, and the property that "an untrusted peer can never supply a country" is one line with one failing input (remove the condition → the spoof test fails). Existing `Visit::fromHeaders` is removed (its callers are tests) — verified by `rg`.
5. **Profile → evaluate → facts, inside one guard** — `App\Redirect\VisitorProfiler::profile(Visit): VisitorProfile` (deviceType, os, browser, isBot, country, language) runs `DeviceDetection` (decision 7), the `CountryResolverInterface` chain (decision 8) and `AcceptLanguage` (decision 9). `App\Redirect\Rules\RuleEvaluator::evaluate(?array $storedRules, VisitorProfile, Visit, Uuid $linkId, string $targetUrl): Resolution` parses the document (decision 1) and applies the fixed order: rules grouped by dimension in the order device → country → language, each group in document order, a rule matching when every listed value list contains the profile's value (a null profile value for a listed dimension = skip); then `VariantPicker` (decision 10) if variants exist; else default. `Resolution` = `(target, ResolvedBy enum, ?variant)`. `RedirectResolver`, after the 410 fast path and before HEAD/record: `try { $profile = …; $resolution = …; } catch (\Throwable $e) { notice('Routing degraded to the default target', ['link_id', 'exception' => $e::class]); $profile = VisitorProfile::unknown(); $resolution = Resolution::default($link->getTargetUrl()); }` — then `location = UtmAppender::append($resolution->target, utm)`, `HEAD` → redirect without recording, else `record($link, $visit, ClickFacts::from($profile, $resolution))`. The guard is the mechanism of "Evaluation never fails the redirect"; it guarantees a 302 for every throwable inside the three steps, and it does not guarantee that a bug is noticed by anything but the `notice` line (the exception class is logged; PHPStan and the unit matrix keep the evaluator honest). Hostile inputs that merely fail to parse (garbage UA, wildcard `Accept-Language`) return null dimensions and never reach the catch — no log record (spec, "Unresolvable dimensions are skipped"). Alternative — evaluate inside the recorder or the controller — rejected: the resolver already owns the decision order and the failure policies; the controller stays HTTP-only.
6. **Anomalous stored documents** — `RuleEvaluator` throws `App\Redirect\Rules\UnusableRulesException` when the parser reports violations for a stored document; the guard of decision 5 turns it into the default target plus one `notice`. No repair, no migration of documents: none exist before this change.
7. **Device detection** (`App\Redirect\Detection\DeviceDetection::detect(Visit): DetectedClient`) — `matomo/device-detector ^6.5`: a `DeviceDetector` per request over `Visit::$userAgent` and `ClientHints::factory()` built from `Visit::$clientHints`; `setCache(new PSR6Bridge($pool))` with the pool `cache.device_detector` (filesystem adapter, `config/packages/cache.yaml`) so the regex database is parsed once per deploy on local disk — no Redis, no network; `setYamlParser(new Yaml\Symfony())` to use the installed `symfony/yaml`; `skipBotDetection(false)`, `discardBotInformation(true)` (a bot yields `isBot = true` and null device/OS). Mapping onto the vocabularies: device name `desktop` → `desktop`, `smartphone` and `phablet` → `smartphone`, `tablet` → `tablet`, any other non-empty name → `other`, empty → null; OS via the library's OS family: `iOS` → `iOS` (iPadOS is in that family), `Android` → `Android`, `Windows` → `Windows`, `Mac` → `macOS`, `GNU/Linux` → `Linux`, any other non-empty family → `other`, unknown → null; browser = client name when the client type is `browser`, `mb_substr(…, 0, 32)`, else null. The class names, the family table and the client-hint factory signature are verified against `vendor/` in task 1.1 before the wrapper is written; the mapping is asserted on fixed user-agent strings in a unit test, so a library update that reclassifies a fixture fails a test rather than a rule. Bots are evaluated like any visitor (they usually have null dimensions and fall to the default); the analytics stage excludes them.
8. **Country resolver chain** — `App\Redirect\Geo\CountryResolverInterface::resolve(Visit): ?string` (upper-case alpha-2 or null). Implementations are tagged `app.country_resolver` with a `key`; `ChainCountryResolver` receives them by `#[AutowireIterator('app.country_resolver', indexAttribute: 'key')]` plus `COUNTRY_RESOLVERS` and, in its constructor, resolves the comma-separated names to instances — an unknown name throws, so a typo fails boot (`debug:container` and a unit test), not a redirect. `HeaderCountryResolver` (`header`): returns `strtoupper(Visit::$proxyCountry)` when it matches `^[A-Za-z]{2}$` and is not `XX`/`T1` (Cloudflare's unknown/Tor markers), else null — trust was already decided in decision 4. `GeoLite2CountryResolver` (`geolite2`): `geoip2/geoip2 ^3.4`; the `Reader` is created lazily on first use through an injected factory closure (the test seam) from `GEOIP_DATABASE_PATH` (`%env(resolve:…)%`, default `%kernel.project_dir%/var/geoip/GeoLite2-Country.mmdb`); if the file is missing or the reader cannot open it, the resolver sets a `disabled` flag, logs one `warning` (`{path_configured: true}` — no path value needed, it is configuration) and returns null for the rest of the process; `AddressNotFoundException` (private, reserved or unknown addresses) → null silently; any other `\Throwable` from a lookup → null and a `notice` `{exception: class}` without the IP. `FixedMapCountryResolver` (`fixed`, `tests/Fixture/`, registered under `when@test` in `config/services.yaml`): constant map `198.51.100.7 → DE`, `198.51.100.44 → US`, `198.51.100.33 → FR`, everything else null — the default test peer `203.0.113.7` stays unmapped so existing click tests are unaffected. Defaults: `.env` `COUNTRY_RESOLVERS=header,geolite2` (the header is free; the database is a file read), `.env.test` `COUNTRY_RESOLVERS=fixed`. Guarantee boundary: geolocation is best-effort; a wrong or missing answer is an unknown country and a skipped rule, never an error or a leaked IP. Not tested against a real GeoLite2 file (the database is licensed and not committed): the reader's behaviour is covered through the factory seam with a stub reader, and the how-to documents the manual check with a downloaded database.
9. **Language** — `App\Redirect\Language\AcceptLanguage::primary(?string $header): ?string`: the header cut to 256 bytes, parsed with `Symfony\Component\HttpFoundation\AcceptHeader::fromString()->all()` (sorted by quality, verified in `vendor/`), the first item's value split at `-`/`_`, lower-cased, accepted only when it matches `^[a-z]{2}$`; anything else null. The request's own `getLanguages()` is not used: it parses the unbounded header and returns invalid values as is.
10. **A/B assignment** — `App\Redirect\Rules\VariantPicker::pick(list<Variant>, Uuid $linkId, string $clientIp, string $userAgent): Variant` computes `crc32($linkId->toRfc4122()."\0".$clientIp."\0".$userAgent) % 100` (NUL separators make the concatenation of FR-RUL-5 unambiguous, as the visitor hash does) and walks the cumulative weights in document order (`value < cumulative` → that variant). CRC32 is the specification's formula and a distribution function, not a security primitive; the salted SHA-256 `visitor_hash` remains the identity at rest. Determinism holds while IP and user agent are unchanged (stated); the distribution property is asserted over 10 000 synthetic distinct visitors within ±3 percentage points for weights 70/30 (a `% 2` regression fails it). When the client IP is unknown (`''`) the formula still yields a deterministic value.
11. **Click facts through the seam** — `App\Click\ClickFacts` (readonly: `?country`, `?deviceType`, `?os`, `?browser`, `bool isBot`, `string resolvedBy`, `?variant`) with `ClickFacts::default()`; `ClickRecorderInterface::record(Link $link, Visit $visit, ClickFacts $facts): RecordOutcome`; `DbalClickRecorder` writes the seven columns from it (the transaction, the conditional UPDATE and the failure policy are unchanged). `ClickFacts::from(VisitorProfile, Resolution)` lives in Redirect (Click does not know Redirect types). Column fit is guaranteed by construction: `variant` ≤ 16 by the name pattern, `resolved_by` ≤ 8 (`language` is 8), `device_type`/`os` from fixed vocabularies ≤ 16, `browser` cut to 32, `country` 2 letters. Row 7 re-implements the same signature with a message carrying the facts.
12. **Configuration and dependencies** — `.env`: `COUNTRY_RESOLVERS=header,geolite2`, `GEOIP_COUNTRY_HEADER=CF-IPCountry`, `GEOIP_DATABASE_PATH=%kernel.project_dir%/var/geoip/GeoLite2-Country.mmdb` with comments (the file is downloaded by the operator, never committed — `var/` is gitignored); `.env.test`: `COUNTRY_RESOLVERS=fixed`. `composer.json`: `matomo/device-detector: ^6.5`, `geoip2/geoip2: ^3.4` (both require PHP ≥ 8.1; transitive `mustangostang/spyc`, `maxmind-db/reader`, `maxmind/web-service-common`); `composer audit` runs in the task; the lock diff is reviewed and the commit is flagged **security-sensitive: dependencies**. No migration.

## Applicability (high tier)

| Question | Applies? | Note |
|---|---|---|
| Crash before/after an external effect | n/a | no new external effect: the click transaction of the previous change is unchanged; detection reads a local cache, GeoLite2 reads a local file; the `notice` of the guard is written after the outcome is known |
| Concurrent writers | n/a | evaluation is pure and per request; no new write; the conditional UPDATE keeps the limit exact (previous change, decision 3) |
| Money rounding | n/a | |
| Empty/zero/null inputs | yes | `rules` null/absent/`[]`/scalar (decision 2); empty value arrays, weight 0, one or five variants, `{"version":1}` alone (decision 1); missing `User-Agent`/`Accept-Language`/client hints → null dimensions, skipped rules, no log (decision 5); unknown client IP `''` → deterministic variant, no country; a document with rules that all skip and no variants → default |
| Authorization boundary | yes | `rules` is written only through operations already guarded by `LINK_EDIT`/`ROLE_USER`; every rule and variant target passes `TargetUrlPolicy`, so a rule cannot open a destination class the plain target could not (open-redirect/SSRF surface unchanged); the country header is honoured only from `TRUSTED_PROXIES` (decision 4, failing input: remove the condition); the redirect stays public and reads no token |
| Deletion/expiry | n/a | unchanged: clicks cascade with the link; expiry precedes evaluation in the resolver |
| Idempotency of retries | n/a | a client retry is a new visit; the deterministic variant makes a retried visitor consistent by construction (decision 10); no new write |

## Risks / Trade-offs

- [Device detection on the hot path costs CPU (regex database)] → PSR-6 filesystem cache warms once per deploy; no network or Redis; the p95 target (NFR-PERF-1) is measured in row 7 once the click write leaves the request; the how-to states that the first requests after a deploy are slower.
- [Library classification drifts with updates] → fixtures of real user agents assert the mapping; an update that reclassifies a fixture fails `make check`, and the mapping table is the one place to adjust.
- [GeoLite2 is licensed and not shipped] → the resolver disables itself with one `warning`; local and CI runs use `header,geolite2` with no file (dev) or the fixed map (test); the how-to documents the download; the header resolver covers Cloudflare-style deployments without any file.
- [A spoofable country header] → honoured only from a trusted proxy (decision 4); tested from an untrusted peer and from `127.0.0.1`.
- [`mixed $rules` bypasses the serializer's type checks] → the constraint is the sole authority and every violation class has an HTTP test; the parser rejects anything that is not an object.
- [Schema file and validator disagree] → parity test on every constant; shared example fixture.
- [A catch-all guard hides evaluation bugs] → the `notice` names the exception class and the link id; the evaluator has a unit matrix and PHPStan level 8; the guard is the specification's requirement (FR-RUL-7), not a convenience.
- [CRC32 modulo 100 is coarse for tiny weights] → weights are integers 1–99 by construction and the distribution test bounds the error at ±3 pp for 10 000 visitors; per-visitor stickiness, not statistical perfection, is the requirement.
- [The recorder signature changes] → intended: the seam gains the facts that row 7's message must carry; all three implementations/callers (recorder, resolver, tests) change in this change; `rg record\(` closes the set.
- [Two new dependencies parse attacker-controlled bytes] → both are widely deployed; inputs are bounded before they reach the libraries; the guard turns any exception into the default target; `composer audit` in the task and the commit flagged as security-sensitive.

## Migration Plan

No database migration. Deploy: `composer install` (two packages), code, then optionally place the GeoLite2 file at `GEOIP_DATABASE_PATH` — the resolver picks it up on the next process start (lazy reader, one attempt per process). Rollback: revert the code; stored documents in `links.rules` are ignored by the previous resolver (it never read the column) and `GET` of a link keeps returning them only through the new resource — after a rollback the field simply disappears from responses.
