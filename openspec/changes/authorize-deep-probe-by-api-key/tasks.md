- [ ] 2.1 `src/Shared/Health/ProbeAuthorizer.php` (design decisions 1–5: `authorize(?string $header): bool`; regex from `ApiKeyHeaderExtractor`, hash from `ApiKeyGenerator::hash()`; `BUDGET_SECONDS = 4.0`, `MEMORY_TTL_SECONDS = 300`; step 1 on `BoundedDatabaseConnection` with connect 2 s — skipped when less than 2 s remain — and `statement_timeout = min(2000, remaining × 1000)`, one `SELECT … JOIN users … WHERE key_hash = :hash`, three-valued outcome verified / denied / unavailable; step 2 on `BoundedRedisConnection` with `min(1.0, remaining)`: `SET probe-auth:<sha256(hash)> 1 EX 300` on verified, `DEL` on denied, `EXISTS` only on unavailable; `warning` `{exception}` for a database or Redis failure, never the key), `src/Shared/Health/HealthController.php`: in `prod`, run the probe when `authorize()` is true, else the existing 404 body. `tests/Unit/Shared/Health/ProbeAuthorizerTest.php` with the two factories replaced by fakes: verified → true + remember; denied → false + forget; unavailable + remembered → true; unavailable + not remembered → false; unavailable + Redis failing → false; a non-key header → false with no I/O; an exhausted budget → false without a Redis call. `tests/Integration/Shared/Health/ProbeAuthorizerTest.php` (real PostgreSQL and Redis, spy logger, rows through `ApiKeyFactory`/`UserFactory`): admin key → true and the memory key exists with a TTL ≤ 300; non-admin, blocked, revoked, expired, unknown → false and the memory key absent; `DATABASE_URL` at a closed port → false within 3 s with the "database unavailable" warning; a stalled statement (`LOCK TABLE api_keys IN ACCESS EXCLUSIVE MODE` held by the test's own transaction) → false within 3 s.
